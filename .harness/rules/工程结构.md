# 工程结构规范（tea）

> 定义"东西放哪里"。与 `编码规范.md`（怎么写代码）、`开发流程规范.md`（怎么走流程）配套。AGENTS.md 是总入口。

## 使用方式（触发条件）

- **新建文件 / 模块 / 目录前**：先查本文档找归属位置，无对应位置时提出，禁止随手新建。
- **涉及目录调整 / 文件移动**：先 Read 目标文件确认归属与引用，再动手。
- **新增后端模块**：对照"目标 Spring Boot 结构"，旧 FastAPI 结构只维护不新增。

# 一、仓库根目录

```
tea/
├── src/  backend/  database/  scripts/  e2e/  public/   # 前端 / 后端 / 库脚本 / 验证脚本 / E2E / 静态资源
├── docs/  .harness/  .agents/  .github/                 # 文档分层 / AI 治理体系 / 项目级技能 / CI 门禁
├── .vscode/ .idea/                                      # 编辑器配置（不提交个人偏好）
├── AGENTS.md  CONTEXT.md  3D_SPEC.md  DESIGN_SPEC.md  TESTING_SPEC.md  DEPLOY.md
└── docker-compose.yml  nginx*.conf  package*.json  vite.config.ts  biome.json
```

> 逐行目录树会漂移，不在此维护——完整清单用 `ls` / glob 现取；目录归属看本节边界规则。

**边界规则**：
- 🔴 密钥文件（`.env*` / `*.pem` / `secrets/`）禁提交，只读 `.env.example`。
- 🟢 构建产物（`dist/` / `dev-dist/` / `__pycache__` / `.venv` / `node_modules` / `test-results`）禁编辑禁提交。

# 二、前端结构（src/）

```
src/
├── views/       # 页面级组件（各自独立目录）
├── components/  # 通用组件（ui/common/brewing/tasting/three）
├── composables/ stores/ services/   # 逻辑 / 状态 / 数据访问（services/{api,storage}）
├── data/        # 静态数据（茶/器/文化，不编造）
└── router/ types/ assets/ plugins/ test/
```

> 子目录清单用 glob 现取；分层与边界判据见下方规则。

**边界规则**：
- 🔴 数据流单向：`views → stores → services`；禁组件直接 import services 绕过 store（读除外）。
- 🔴 `src/components/three/` 只做视觉层，状态机在 store，见 `3D_SPEC.md`。
- 🟢 页面级组件放 `views/` 各自目录（`views/brew/`、`views/taste/` 等），通用件放 `components/`。

# 三、后端结构（旧 FastAPI，过渡期）

```
backend/     # 旧 FastAPI：app/{models,routers,schemas,services} + config/database/deps/errors/middleware
             # + migrations/(Alembic) + seeds/ + tests/(pytest) + requirements*.txt
```

> 过渡期结构照代码现读；新代码不按此结构写（见 §四）。

**边界规则**：
- 🔴 旧 FastAPI **仅维护不新增**；新功能一律按 Spring Boot 结构走（见 §四）。
- 🟢 重写完成后 `backend/app` 旧目录整段退役，迁移脚本在 `changes/` 留档。

# 四、后端目标结构（Spring Boot 3.5 + JPA，重写中）

```
backend/                          # Maven 工程
├── pom.xml                       # 依赖版本锁定（parent + properties）
├── src/main/java/com/tea/
│   ├── TeaApplication.java       # 启动类
│   ├── common/                   # 跨模块公共
│   │   ├── exception/            #   BusinessException 体系 + @RestControllerAdvice
│   │   ├── response/             #   ApiResponse<T>
│   │   ├── error-code/           #   全局错误码表
│   │   ├── config/               #   线程池 / 缓存 / 序列化配置
│   │   └── util/                 #   工具（脱敏等）
│   ├── auth/                     # 认证授权（Security + JWT）
│   ├── tea/                      # 茶叶领域（entity/repository/service/controller）
│   ├── record/                   # 品鉴记录（幂等 client_id）
│   ├── culture/                  # 茶文化知识
│   ├── ware/                     # 茶器
│   └── ai/                       # Spring AI Alibaba（代理 /api/v1/ai/*）
│       ├── controller/           #   入口
│       ├── service/              #   调用编排 + 降级
│       ├── prompt/               #   prompt 模板（版本管理）
│       └── agent/                #   RAG / agent 编排
├── src/main/resources/
│   ├── application.yml           # 公共配置
│   ├── application-{env}.yml     # dev/staging/prod
│   └── db/migration/             # Flyway 迁移脚本
└── src/test/java/                # 单测 + 集成测试（Testcontainers）
```

**分层约束**（每个业务域内）：
- 🔴 `controller → service → repository` 单向依赖；Controller 不写业务。
- 🔴 四层对象分离：`dto`（入）→ `entity`（持久）→ `vo`（出）→ `model`（领域）；Entity 禁直接出参。
- 🟢 每个业务域 `entity/repository/service/controller` 四件套齐备，域间通过 service 调用（禁直接依赖对方 repository）。

# 五、.harness 治理结构

```
.harness/
├── rules/     # 规则三件套（工程结构 / 开发流程规范 / 编码规范·红线 15 条）
├── wiki/      # AI 上下文四件套（business-model / api-contract / data-model / glossary）
├── changes/   # 变更追踪，与 git 分支同名（_template + {feat-name}/）
└── skills/    # 技能三族（main-dev / biz-dev / trouble-shooting，按需渐进式加载）
（子代理实际位于 .claude/agents/：code-reviewer / consistency-verifier / red-line-auditor）
```

**边界规则**：
- 🟢 `wiki/` 是 AI 上下文来源，编码前按需读取（≤3 份，见开发流程规范 token 限制）。
- 🟢 `changes/` 与 git 分支强绑定：分支合并即变更闭合，不产生游离记录。

# 六、docs 分层

```
docs/
├── ADR/            # 架构决策记录（ADR-001~021 + 新增 ADR-0XX，禁止塞进 CONTEXT.md）
├── architecture/ api/ prd/ promotion/ screenshots/ skills/   # 架构 / 接口 / 需求 / 物料 / 截图 / 技能人读页
├── plans/          # 迭代计划与待办（PLAN-* / TODO-PRIORITY 类）
├── reference/      # 稳定参考（error-codes.md 错误码表）
├── superpowers/    # 外部参考计划留档（plans/2026-09-*）
└── 根级策略文档     # agent-eval-baseline / DATA_POLICY / HANDOFF-* / research-* 按主题留根
```

**边界规则**：
- 🔴 架构决策写 ADR，不写进 CONTEXT.md；执行级决策写 TASK_RECORD / 变更记录。
- 🟢 PRD 保留版本号（v0.1/v0.2），新版本不覆盖旧版本，便于对比。
- 🟢 docs 根级策略文档（基线/复盘/交接/评估）不入子目录；新增子目录前先更新本分层。
- 🟢 **文档元信息头（Harness 285 doc-gardening 前提）**：docs/ 下每个 .md 头部带 frontmatter `last_updated / status / owner`，status ∈ active | draft | deprecated；verify-harness.cjs 据此扫描过期文档。新计划类文档入 `docs/plans/`，新稳定参考（错误码/规格）入 `docs/reference/`。
