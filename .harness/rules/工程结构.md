# 工程结构规范（tea）

> 定义"东西放哪里"。与 `编码规范.md`（怎么写代码）、`开发流程规范.md`（怎么走流程）配套。AGENTS.md 是总入口。

## 使用方式（触发条件）

- **新建文件 / 模块 / 目录前**：先查本文档找归属位置，无对应位置时提出，禁止随手新建。
- **涉及目录调整 / 文件移动**：先 Read 目标文件确认归属与引用，再动手。
- **新增后端模块**：对照"目标 Spring Boot 结构"，旧 FastAPI 结构只维护不新增。

# 一、仓库根目录

```
tea/
├── src/                     # 前端（Vue 3.5 + TS + Pinia + Tailwind 4 + TresJS）
├── backend/                 # 后端（旧 FastAPI，重写中；目标 Spring Boot 见 §四）
├── database/                # 数据库脚本 / ER 资产
├── docs/                    # 文档分层（见 §五）
├── scripts/                 # Node 验证脚本（verify-*.cjs / audit-*.cjs / deploy-*.ps1）
├── e2e/                     # Playwright E2E
├── public/                  # 静态资源（含 /3d/ KTX2、PWA）
├── .harness/                # AI 编码治理体系（rules / wiki / changes / skills / agents）
├── .agents/                 # 项目级技能（db-migration 等）
├── .github/                 # CI workflows（合并门禁）
├── .vscode/ .idea/          # 编辑器配置（不提交个人偏好）
├── AGENTS.md                # AI 协作规则总入口
├── CONTEXT.md               # 术语 + ADR 索引 + 架构关键词
├── 3D_SPEC.md               # 3D 茶空间约束
├── DESIGN_SPEC.md           # 设计基线（色令牌/字体角色）
├── TESTING_SPEC.md          # 测试规范
├── DEPLOY.md                # 部署（Docker Compose 为主，旧 Windows 原生保留参考）
├── docker-compose.yml       # 部署编排单元
├── nginx.conf / nginx-windows.conf
├── package.json / package-lock.json
├── vite.config.ts / biome.json / playwright.config.ts
└── .env*  (只读 .env.example，密钥不入库)
```

**边界规则**：
- 🔴 密钥文件（`.env*` / `*.pem` / `secrets/`）禁提交，只读 `.env.example`。
- 🟢 构建产物（`dist/` / `dev-dist/` / `__pycache__` / `.venv` / `node_modules` / `test-results`）禁编辑禁提交。

# 二、前端结构（src/）

```
src/
├── views/            # 页面级组件（Home/Brew/Taste/Garden/TeaRoom/... 各自独立目录）
├── components/       # 通用组件
│   ├── ui/           #   UI 基础件（按钮/弹窗/表单）
│   ├── common/       #   业务通用件
│   ├── brewing/      #   冲泡流程件
│   ├── tasting/      #   品鉴流程件
│   ├── three/        #   3D 视觉件（只做视觉层，禁改状态机）
│   └── __tests__/
├── composables/      # Vue composables（可复用逻辑，含 __tests__）
├── stores/           # Pinia 业务状态（含 __tests__）
├── services/         # 数据访问
│   ├── api/          #   后端 API 调用（统一走 src/services/api.ts）
│   ├── storage/      #   IndexedDB（Dexie，统一走 src/services/storage.ts）
│   └── __tests__/
├── data/             # 静态数据（茶/器/文化，tea-tasting 基准，不编造）
├── router/           # 路由（懒加载 + 守卫）
├── types/            # 全局类型（与后端 VO 对应）
├── assets/           # 静态资源（teas/ wares/）
├── plugins/          # 插件安装
└── test/             # 测试工具 / mocks
```

**边界规则**：
- 🔴 数据流单向：`views → stores → services`；禁组件直接 import services 绕过 store（读除外）。
- 🔴 `src/components/three/` 只做视觉层，状态机在 store，见 `3D_SPEC.md`。
- 🟢 页面级组件放 `views/` 各自目录（`views/brew/`、`views/taste/` 等），通用件放 `components/`。

# 三、后端结构（旧 FastAPI，过渡期）

```
backend/
├── app/
│   ├── models/       # SQLAlchemy 模型（culture/knowledge/record/tea/user/ware）
│   ├── routers/      # 路由（ai/auth/culture/records/teas/teawares）——只做参数与响应
│   ├── schemas/      # Pydantic v2（入参/出参分离）
│   ├── services/     # 业务逻辑
│   ├── config.py     # 配置
│   ├── database.py   # 连接
│   ├── deps.py       # 依赖
│   ├── errors.py / exceptions.py  # 异常体系（BusinessError 子类）
│   └── middleware.py
├── migrations/       # Alembic 迁移（过渡期；重写后走 Flyway）
├── seeds/            # 数据种子
├── tests/            # pytest
└── requirements*.txt / .venv（过渡期，重写后移除）
```

**边界规则**：
- 🔴 旧 FastAPI **仅维护不新增**；新功能一律按 Spring Boot 结构走（见 §四）。
- 🟢 重写完成后 `backend/app` 旧目录整段退役，迁移脚本在 `changes/` 留档。

# 四、后端目标结构（Spring Boot 3.5 + JPA，重写中）

```
backend/                          # Maven 工程
├── pom.xml                       # 依赖版本锁定（parent + properties）
├── src/main/java/com/tea/
│   ├── TeaApplication.java       # 启动类
│   ├── common/                   # 跨模块公共
│   │   ├── exception/            #   BusinessError 体系 + @RestControllerAdvice
│   │   ├── response/             #   ApiResponse<T>
│   │   ├── error-code/           #   全局错误码表
│   │   ├── config/               #   线程池 / 缓存 / 序列化配置
│   │   └── util/                 #   工具（脱敏等）
│   ├── auth/                     # 认证授权（Security + JWT）
│   ├── tea/                      # 茶叶领域（entity/repository/service/controller）
│   ├── record/                   # 品鉴记录（幂等 client_id）
│   ├── culture/                  # 茶文化知识
│   ├── ware/                     # 茶器
│   └── ai/                       # Spring AI Alibaba（代理 /api/ai/*）
│       ├── controller/           #   入口
│       ├── service/              #   调用编排 + 降级
│       ├── prompt/               #   prompt 模板（版本管理）
│       └── agent/                #   RAG / agent 编排
├── src/main/resources/
│   ├── application.yml           # 公共配置
│   ├── application-{env}.yml     # dev/staging/prod
│   └── db/migration/             # Flyway 迁移脚本
└── src/test/java/                # 单测 + 集成测试（Testcontainers）
```

**分层约束**（每个业务域内）：
- 🔴 `controller → service → repository` 单向依赖；Controller 不写业务。
- 🔴 四层对象分离：`dto`（入）→ `entity`（持久）→ `vo`（出）→ `model`（领域）；Entity 禁直接出参。
- 🟢 每个业务域 `entity/repository/service/controller` 四件套齐备，域间通过 service 调用（禁直接依赖对方 repository）。

# 五、.harness 治理结构

```
.harness/
├── rules/            # 规则三件套
│   ├── 工程结构.md     #   本文档
│   ├── 开发流程规范.md #   十阶段流水线 + 分支提交 + 回滚 + 多 agent + review
│   └── 编码规范.md     #   四域编码质量标准（红线 15 条）
├── wiki/             # AI 编码上下文
│   ├── business-model.md   # 业务模型（领域/实体/流程）
│   ├── api-contract.md     # 接口协议（约定 + 版本化）
│   ├── data-model.md       # 数据模型（表/字段/索引/迁移）
│   └── glossary.md         # 领域术语（避免 AI 造词）
├── changes/          # 变更追踪（与 git 分支 feature/{feat-name} 同名）
│   ├── _template/    #   新建功能时复制（summary + db-migrations + rollback 模板）
│   └── {feat-name}/
│       ├── summary.md        # 需求+方案+影响
│       ├── db-migrations.sql # 迁移（up）
│       └── rollback.sql      # 回滚（down）
├── skills/           # 技能（按需渐进式加载）
│   ├── main-dev/     #   主流程（request-analysis/coding/unit-test/expert-review/...）
│   ├── biz-dev/      #   业务专项（crud/分页/文件/ai-agent/rag/fallback/...）
│   └── trouble-shooting/ # 故障排查（慢SQL/OOM/CPU/...）
（子代理实际位于 .claude/agents/：code-reviewer / consistency-verifier / red-line-auditor）
```

**边界规则**：
- 🟢 `wiki/` 是 AI 上下文来源，编码前按需读取（≤3 份，见开发流程规范 token 限制）。
- 🟢 `changes/` 与 git 分支强绑定：分支合并即变更闭合，不产生游离记录。

# 六、docs 分层

```
docs/
├── ADR/              # 架构决策记录（ADR-001~013 + 新增 ADR-0XX，禁止塞进 CONTEXT.md）
├── architecture/     # 系统架构（system-overview 合并分层/边界/数据流）
├── api/              # 接口文档（旧 FastAPI 端点）
├── prd/              # 需求文档（PRD-spring-ai-refactor-v2.md 现行，带版本号；模板见 prd/_template/requirements-template.md）
├── plans/            # 迭代计划与待办（PLAN-* / TODO-PRIORITY 类；285 current-sprint/backlog 对应物）
├── reference/        # 稳定参考（error-codes.md 错误码表；springdoc OpenAPI spec 接入后入此）
├── promotion/        # 运营/宣传物料
├── screenshots/      # 截图证据
├── skills/           # 核心技能人读审查页（与 .agents/skills 同名技能）
├── superpowers/      # 外部参考计划留档（plans/2026-09-*）
└── 根级策略文档      # agent-eval-baseline / DATA_POLICY / HANDOFF-* / OPTIMIZATION_PLAN / research-* 等按主题留根，不入子目录
```

**边界规则**：
- 🔴 架构决策写 ADR，不写进 CONTEXT.md；执行级决策写 TASK_RECORD / 变更记录。
- 🟢 PRD 保留版本号（v0.1/v0.2），新版本不覆盖旧版本，便于对比。
- 🟢 docs 根级策略文档（基线/复盘/交接/评估）不入子目录；新增子目录前先更新本分层。
- 🟢 **文档元信息头（Harness 285 doc-gardening 前提）**：docs/ 下每个 .md 头部带 frontmatter `last_updated / status / owner`，status ∈ active | draft | deprecated；verify-harness.cjs 据此扫描过期文档。新计划类文档入 `docs/plans/`，新稳定参考（错误码/规格）入 `docs/reference/`。
