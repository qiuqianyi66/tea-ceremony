# 编码规范（tea 企业级）

> 本文档是「怎么写代码」的唯一权威质量标准（红线 + 强规范 + 建议三级）。工程结构、开发流程见同目录 `工程结构.md`、`开发流程规范.md`。AGENTS.md 是总入口，不重复维护。

## 使用方式（触发条件）

- **任何编码实现前**：读取本文档，按对应域执行（后端/前端/数据库/部署）。
- **代码评审时**：以本文档为评审依据，逐条核对红线与强规范。
- **数据库变更前**：必读「三、数据库规范」，迁移必须成对可回滚。
- **部署前**：对照「四、部署规范」十阶段门禁与回滚路线。

## 优先级体系

- 🔴 **红线**：违反 = 禁止提交 / 评审不通过 / 必须修复后才能合入。
- 🟢 **强规范**：默认必须，特例需在代码注释或评审中说明理由。
- ⚪ **建议**：团队约定，鼓励但不强制。

# 一、后端规范（Spring Boot 3.5 + JPA + Spring AI Alibaba）

## 1. 分层与依赖方向

- 🔴 **单向依赖**：Controller → Service → Repository / 外部适配器。禁止反向依赖、禁止跨层调用（Controller 直接查 Repository 视为违规）。
- 🔴 Controller 只做三件事：声明路径与鉴权、调用 Service、声明响应模型。**禁止在 Controller 写业务逻辑、写数据库查询、处理异常**。
- 🟢 按业务域分包：`auth` / `tea` / `record` / `culture` / `ai`；禁止循环依赖（依赖倒置 + 接口隔离）。
- 🟢 构造器注入：`final` 字段 + `@RequiredArgsConstructor`；**禁 `@Autowired` 字段注入**。

## 2. 异常体系

- 🔴 统一继承 `BusinessException` 基类体系：`BadRequestException` / `UnauthorizedException` / `NotFoundException` / `ConflictException`，位于 `common/exception/`。
- 🔴 **禁止裸抛 `RuntimeException` / `Exception`**；禁止 `catch(Exception)` 吞异常（catch 后必须处理或记录并重抛业务异常）。
- 🟢 全局 `@RestControllerAdvice` 统一转 `ApiResponse<T>`；技术异常（DB/IO/JSON）映射 500 + 错误码，**不向前端泄露堆栈**。
- 🟢 业务异常必须携带 `errorCode + message`；日志分级：业务预期失败 `warn`，非预期 `error`（带堆栈）。

## 3. 对象模型分离

- 🔴 **四层对象**：Request DTO（入参）→ Entity（持久化）→ VO（出参）→ 内部 Model（领域）。职责不混用。
- 🔴 **Entity 禁止直接出参 / 入参**（防字段泄露如 `isDeleted`、防层间耦合）。
- 🟢 对象转换统一 MapStruct（编译期映射），**禁 BeanUtils 反射拷贝**（性能差 + 错误隐蔽）。
- 🟢 金额 `Integer`（分）、时间统一 `LocalDateTime` / `Instant`、枚举加 `@Converter`。

## 4. 事务与数据一致性

- 🟢 写方法 `@Transactional(rollbackFor = Exception.class)`；只读方法 `@Transactional(readOnly = true)`；事务边界 = 业务用例边界。
- 🔴 **禁事务内做远程调用 / 消息发送 / 异步任务**（用 `TransactionSynchronization.afterCommit` 回调）。
- 🟢 幂等：写接口必须幂等——`client_id` 唯一键 + 唯一索引 + 冲突处理（品鉴记录承重墙）。
- 🟢 传播行为显式声明（REQUIRED / REQUIRES_NEW）；禁事务内 `sleep` / 循环重试。

## 5. 数据访问（JPA）

- 🟢 Repository 继承 `JpaRepository`；复杂查询用 Specification / @Query（**命名参数防注入**，禁字符串拼接）。
- 🔴 **禁 N+1**：fetch join / `@EntityGraph` / 批量查询；大列表必分页（`PageRequest`），禁全表查询。
- 🟢 乐观锁 `@Version`；软删除统一 `@SQLDelete` + `@SQLRestriction`（查询默认过滤已删）。
- 🟢 审计字段统一（created_at / updated_at / created_by）用 `@MappedSuperclass`。
- 🔴 迁移走 Flyway（见数据库规范），**禁生产 `ddl-auto: update`**。

## 6. 校验与防御

- 🟢 入参 Bean Validation（`@Valid` + 分组校验）；写操作 DTO 校验注解齐全。
- 🟢 输出脱敏：手机 / 邮箱 / 身份证在 VO 层统一处理；评分 / 金额范围校验（八维评分 0-100 等）。
- 🟢 RESTful 动词：GET 查 / POST 增 / PUT 改 / DELETE 删；统一 `ApiResponse<T>`：`success(data)` / `paginated(items,total,page,size)` / `success()`。

## 7. 并发与线程

- 🔴 **禁 `Executors.newFixedThreadPool` / `newCachedThreadPool`**（无界队列必 OOM）；统一 `ThreadPoolTaskExecutor` Bean（有界队列 + 显式拒绝策略）。
- 🟢 `@Async` 必须指定 executor + 错误处理；共享缓存用 Caffeine（容量+过期）或 Redis，**禁 HashMap 做本地缓存**。

## 8. 安全规范

- 🟢 Spring Security + JWT；方法级 `@PreAuthorize`；**资源归属校验**（用户私有数据防越权，userId 必须匹配当前登录人）。
- 🔴 SQL 注入：JPA 参数化禁拼接；XSS：输出转义；Token / 密码 / 密钥**禁入日志**。
- 🔴 `.env*` / `*.pem` / secrets 禁入库；依赖安全审计（npm audit / 后端依赖扫描）。

## 9. AI 集成规范（tea 特有）

- 🔴 **AI 请求必须走后端代理 `/api/ai/*`，禁止前端直连第三方 AI**。
- 🔴 降级链不可删：AI 不可用时回退规则引擎（前端 `teaAI.ts` 承重墙 + 后端 fallback 策略）。
- 🟢 Prompt 版本管理（`agent_prompts` 表 + 灰度）；输出 Schema 强校验（未知版本拒绝）。
- 🟢 AI 调用超时 / 重试 / 熔断；token 成本计量告警；敏感数据不入 prompt。

## 10. 日志与可观测性

- 🟢 统一 logback 配置：日志级别（开发 DEBUG / 生产 INFO+）、模式含 traceId（MDC 贯穿请求）。
- 🟢 关键业务动作埋点（登录 / 品鉴提交 / AI 请求），指标用 Micrometer（错误率 / 延迟 / 缓存命中 / AI token 消耗）。
- 🟢 禁在日志打印请求体全文 / 敏感字段；日志必须可关联（traceId / userId）。
- 🟢 慢查询、AI 超时、降级触发必须告警（阈值与通道见 `开发流程规范.md`）。

## 11. 配置管理

- 🟢 配置分层：`application.yml`（公共）+ `application-{env}.yml`（dev / staging / prod）；**禁硬编码**。
- 🟢 敏感配置走环境变量 / `@ConfigurationProperties` 类型安全绑定；**禁密钥写进 yml 提交**。
- 🟢 配置变更走 PR 评审；生产配置与代码解耦（env_file / Vault 可选）。

## 12. 缓存规范

- 🟢 本地缓存 Caffeine：显式容量 + 过期 + 统计；Redis 键统一前缀 `tea:{module}:{business}:{id}`，**必须设 TTL**。
- 🟢 缓存与 DB 一致性：先写库再删缓存（或延迟双删）；禁无 TTL 的无界缓存。
- 🟢 穿透（空值缓存）/ 击穿（互斥锁）/ 雪崩（过期时间加抖动）防护；缓存内容与业务版本对应（Schema 变更时缓存失效策略）。

## 13. 定时任务

- 🟢 `@Scheduled` 显式 cron / fixedDelay（禁 fixedRate 依赖执行时长）；任务方法幂等。
- 🟢 多实例部署下用分布式锁（ShedLock）防重复执行；任务失败告警 + 重试有界。

## 14. 文件与上传

- 🟢 上传校验：大小上限、MIME 白名单、文件名安全（禁用户原始文件名直存，用 UUID 重命名）。
- 🟢 存储路径外置配置；下载接口鉴权（禁直接暴露静态路径给未登录用户）；头像 / 茶照片首版可延后。

## 15. API 设计

- 🟢 统一 `/api/v1/{resource}` 前缀；**API 版本化**（破坏性变更升 v2，禁静默改 v1 语义）。
- 🟢 全局错误码表（`common/error-code/`），错误码稳定、可查、不随文案变化。
- 🟢 分页契约统一（page/size + 上限 size ≤ 100）；写接口幂等（client_id 头或字段）。

## 16. 测试规范

- 🟢 Service 纯逻辑单测（mock Repository 边界）；Controller 用 `@WebMvcTest`；**禁 mock 内部协作者**（只 mock 跨进程边界：网络 / DB / 时钟）。
- 🟢 集成测试 Testcontainers PostgreSQL；迁移 upgrade / downgrade 往返测试。
- 🟢 命名 `given_when_then`；新增代码覆盖率 ≥ 80%，核心逻辑 100%。

# 二、前端规范（Vue 3.5 + TS strict + Pinia 4 + Tailwind 4 + TresJS + PWA）

## 17. Vue 组件

- 🔴 Composition API + `<script setup lang="ts">`，**禁 Options API**；组件 ≤ 200 行（超了拆）。
- 🟢 Props / Emits 全类型；副作用在 onMounted / onUnmounted 管理；多词 PascalCase 命名。

## 18. 类型安全

- 🔴 TS strict；**禁 `any`、禁 `@ts-ignore`**（特例需审批）；API 返回类型与后端 VO 对应。

## 19. 状态与数据流

- 🔴 单向数据流：views → stores → services；业务状态走 Pinia（`src/stores/`），局部用 ref/reactive。
- 🟢 IndexedDB 统一 `src/services/storage.ts`；API 统一 `src/services/api.ts`。

## 20. 路由与权限

- 🟢 路由懒加载（`() => import(...)`）；路由守卫统一（登录态 / 角色）；404 兜底页。
- 🟢 敏感路由按角色校验（前端防呆，**权限以后端为准**）；动态路由（如需）有类型约束。

## 21. 表单与交互

- 🟢 表单校验与后端一致（schema 同源或规则对齐）；提交防抖 / loading；失败保留输入 + 友好提示。
- 🟢 离线场景乐观更新（先写 IndexedDB 再同步，`sync_status` 流转）；操作反馈统一 toast / 五态。

## 22. 错误监控与埋点

- 🟢 全局错误捕获（`window.onerror` / Vue `errorHandler`）上报；错误边界组件兜底。
- ⚪ 关键行为埋点（页面浏览 / 品鉴提交）与后端 traceId 关联；性能指标（Web Vitals）可选上报。

## 23. 样式与设计令牌

- 🟢 Tailwind 4 工具类，禁自定义 CSS 文件（组件内 scoped 除外）；色值 / 间距 / 圆角 / 阴影走 `DESIGN_SPEC.md` 令牌，禁硬编码色值。
- 🔴 设计门禁：改 UI 前先输出 Design Read（taste 三拨盘）；禁 AI 默认痕迹（Inter 默认 / AI 紫渐变 / 三等分卡片 / emoji 图标 / 玻璃拟态装饰）。

## 24. 3D（TresJS / Three）

- 🔴 `src/components/three/` **只做视觉层，不改状态机**（`3D_SPEC.md` 约束）。
- 🔴 禁直接创建 renderer（统一 TresJS）；资源按需加载；KTX2 压缩纹理。

## 25. 离线优先与性能

- 🔴 离线降级链保留（`teaAI.ts` 承重墙禁删禁削弱）；视频不本地化。
- 🟢 懒加载 / 虚拟列表（大列表）；Core Web Vitals（LCP < 2.5s / INP < 200ms / CLS < 0.1）；`min-h-[100dvh]` 禁 `h-screen`。
- 🟢 构建分包：Vite 手动 chunk 拆分（vendors / three / ai），chunk 命名稳定；包体积预算（> 200KB 告警）。

## 26. 可访问性与边界

- 🟢 触控目标 ≥ 44px；状态五态齐全（hover / disabled / loading / error / empty）；对比度 ≥ 4.5:1。
- 🟢 键盘导航 / 焦点环 / ARIA 语义；`prefers-reduced-motion` 降级；错误边界组件。

# 三、数据库规范（PostgreSQL + Flyway）

## 27. 迁移与回滚（核心红线）

- 🔴 **Schema 变更只走 Flyway**：`db-migrations.sql` 成对存在，`changes/{feat-name}/` 含 `summary.md + db-migrations.sql + rollback.sql`，与 git 分支 `feature/{feat-name}` 同名。
- 🔴 **每个迁移必须可回滚**：down 脚本成对，upgrade / downgrade 往返测试通过才可提交。
- 🔴 **禁生产 `ddl-auto: update` / `create`**；禁手改已应用的迁移文件（追加新迁移，不修改历史）。

## 28. 模型与字段

- 🟢 软删除统一（`@SQLDelete` + `@SQLRestriction`，前端 VO 禁透出 `isDeleted` 等内部字段）。
- 🟢 金额 `Integer`（分）、时间 `LocalDateTime`、命名规范（表名 snake_case 复数，字段 snake_case）。
- 🟢 审计字段统一（created_at / updated_at / created_by）。

## 29. 命名与约束

- 🟢 索引命名 `ix_{table}_{col}`、唯一约束 `uk_{table}_{col}`、外键 `fk_{table}_{col}`，全部显式声明。
- 🟢 唯一约束覆盖幂等键（`client_id` + 用户维度）；CHECK 约束覆盖评分范围（0-100 / 工艺系数 0.5-2.0）。

## 30. 索引与查询

- 🟢 查询条件 / 外键 / 排序字段按需建索引（迁移脚本中显式声明）；分页 `Page<T>`，含条件分支注意索引可用性。
- 🟢 大列表禁全表扫描；禁循环内查询（N+1）；批量操作用批量接口；慢查询（≥ 100ms）纳入告警。

## 31. 性能与运维

- 🟢 连接池 HikariCP 显式上限（禁默认无界）；备份策略：pg_dump 每日 + 保留 14 天（`scripts/backup-postgres.ps1`）。
- 🟢 恢复演练定期执行；Schema 大变更（加列默认值 / 重建索引）评估锁表窗口，走预发验证。

# 四、部署规范（Docker Compose + 十阶段流水线）

## 32. 流水线门禁

- 🔴 十阶段流水线（需求→方案→拆分→编码→单测→评审→集成→预发→部署→观测）**串行推进**：阶段 N 的 Quality Gate 未满足，禁止进入阶段 N+1。
- 🔴 阶段 8-10 由 deploy-verify 承担：staging 验证（含冒烟）→ 部署脚本执行成功 + 冒烟通过 → 30 分钟观测期无异常。
- 🟢 小改动可合并阶段 1-3，但 `summary.md` **不可省略**；红线检查与冒烟验证任何场景**不可省略**。

## 33. 部署单元与环境

- 🟢 **docker-compose.yml 为部署单元**（backend / frontend / postgres / nginx），环境变量外置（`.env.example` 只读参考）。
- 🟢 环境隔离：dev / staging / prod 三套 compose override；健康检查（`/actuator/health`）+ liveness/readiness 探针。
- 🟢 镜像标签规范（`git sha` 或语义版本），生产部署前备份 DB + 确认边界。

## 34. CI/CD 门禁

- 🟢 CI 全绿（type-check + build + test + 迁移测试 + Compose 校验）才可 MR；评审（阶段 6）通过无 🔴。
- 🟢 构建产物校验（镜像可启动 + 冒烟）；生产发版走审批（发布窗口周二~周四）。

## 35. 回滚路线表

| 失败阶段 | 回滚策略 | 触发条件 |
|---|---|---|
| 编码实现 | `git checkout` 丢弃变更 | 编译失败 |
| 数据库迁移 | 执行 `rollback.sql` | 迁移后应用异常 |
| 部署 | 回滚镜像 / 版本标签 | 冒烟失败 / 观测异常 |
| 线上观测 | 走回滚路线回到预发 | 30 分钟内指标越基线 |

## 36. 监控与告警

- 🟢 指标：错误率 / 延迟（P50/P99）/ 资源（CPU/内存/磁盘）/ AI token 成本；观测期 30 分钟无异常才算完成。
- 🟢 告警通道明确（日志 / 指标 / 异常分类处理见 `开发流程规范.md` 与 Trouble-shooting 技能）。

## 37. 分支与提交

- 🟢 特性分支 `feature/{feat-name}`（与 `.harness/changes/{feat-name}` 同名）；修复分支 `fix/{issue-or-bug-desc}`；`main` 保护分支只接受 MR 合入。
- 🔴 Commit 用 conventional commits：`type(scope): message`（feat/fix/refactor/test/docs/chore），subject ≤ 72 字符。
- 🟢 评审（阶段 6）通过 + CI 全绿后才可发起 MR；禁 force push main。

# 六、自检清单（提交 / 评审前逐项）
