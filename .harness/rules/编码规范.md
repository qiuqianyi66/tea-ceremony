# 编码规范（tea 企业级）

> 「怎么写代码」的唯一权威（🔴 红线 / 🟢 强规范 / ⚪ 建议三级）。目录结构见 `工程结构.md`，流程见 `开发流程规范.md`；AGENTS.md 是总入口，不重复维护。

**触发**：编码前按域执行（后端 §1-16 / 前端 §17-26 / 数据库 §27-31 / 部署 §32-37）；评审以本文为依据；库变更前必读 §27；部署前对照 §32-36。
**优先级**：🔴 违反 = 禁止提交 / 评审不通过 / 必须修复才合入；🟢 默认必须，特例需注释或评审说明理由；⚪ 鼓励不强制。

# 一、后端规范（Spring Boot 3.5 + JPA + Spring AI Alibaba）

## 1. 分层与依赖方向
- 🔴【R1】单向依赖：Controller → Service → Repository / 外部适配器。禁反向依赖、禁跨层调用（Controller 直查 Repository 视为违规）。
- 🔴【R1】Controller 只做三件事：声明路径与鉴权、调用 Service、声明响应模型。禁写业务逻辑、禁查库、禁处理异常。
- 🟢 按业务域分包 `auth`/`tea`/`record`/`culture`/`ai`；禁循环依赖（依赖倒置 + 接口隔离）。
- 🟢 构造器注入：`final` 字段 + `@RequiredArgsConstructor`；禁 `@Autowired` 字段注入。

## 2. 异常体系
- 🔴【R2】统一继承 `BusinessException` 基类体系（`common/exception/`）：`BadRequestException`/`UnauthorizedException`/`NotFoundException`/`ConflictException`；禁裸抛 `RuntimeException`/`Exception`。
- 🔴【R2】禁 `catch(Exception)` 吞异常——catch 后必须处理，或记录并重抛业务异常。
- 🟢 全局 `@RestControllerAdvice` 统一转 `ApiResponse<T>`；技术异常（DB/IO/JSON）映射 500 + 错误码，禁向前端泄露堆栈。
- 🟢 业务异常必须带 `errorCode + message`；日志分级：业务预期失败 `warn`，非预期 `error`（带堆栈）。

## 3. 对象模型分离
- 🔴【R3】四层对象：Request DTO（入参）→ Entity（持久化）→ VO（出参）→ 内部 Model（领域）；职责不混用。
- 🔴【R3】Entity 禁直接出参 / 入参（防 `isDeleted` 等字段泄露、防层间耦合）。
- 🟢 对象转换统一 MapStruct（编译期映射）；禁 BeanUtils 反射拷贝。
- 🟢 金额 `Integer`（分）、时间 `LocalDateTime`/`Instant`、枚举加 `@Converter`。

## 4. 事务与数据一致性
- 🟢 写方法 `@Transactional(rollbackFor = Exception.class)`；只读方法 `@Transactional(readOnly = true)`；事务边界 = 业务用例边界。
- 🔴【R4】禁事务内做远程调用 / 消息发送 / 异步任务（改用 `TransactionSynchronization.afterCommit`）。
- 🟢【R5】幂等：写接口必须幂等——`client_id` 唯一键 + 唯一索引 + 冲突处理（品鉴记录承重墙）。
- 🟢 传播行为显式声明（REQUIRED/REQUIRES_NEW）；禁事务内 `sleep`/循环重试。

## 5. 数据访问（JPA）
- 🟢 Repository 继承 `JpaRepository`；复杂查询用 Specification/`@Query`（命名参数防注入，禁字符串拼接）。
- 🔴【R6】禁 N+1：fetch join / `@EntityGraph` / 批量查询；大列表必分页（`PageRequest`），禁全表查询。
- 🟢【R6】乐观锁 `@Version`；软删除统一 `@SQLDelete` + `@SQLRestriction`（查询默认过滤已删）。
- 🟢 审计字段（created_at/updated_at/created_by）用 `@MappedSuperclass`。
- 🔴 迁移走 Flyway（§27）；禁生产 `ddl-auto: update`。

## 6. 校验与防御
- 🟢 入参 Bean Validation（`@Valid` + 分组校验）；写操作 DTO 校验注解齐全。
- 🟢 输出脱敏：手机/邮箱/身份证在 VO 层统一处理；评分/金额范围校验（八维评分 0-100）。
- 🟢 RESTful 动词：GET 查 / POST 增 / PUT 改 / DELETE 删；统一 `ApiResponse<T>`：`success(data)`/`paginated(items,total,page,size)`/`success()`。

## 7. 并发与线程
- 🔴【R8】禁 `Executors.newFixedThreadPool`/`newCachedThreadPool`（无界队列必 OOM）；统一 `ThreadPoolTaskExecutor` Bean（有界队列 + 显式拒绝策略）。
- 🟢 `@Async` 必须指定 executor + 错误处理；共享缓存用 Caffeine（容量+过期）或 Redis；禁 HashMap 做本地缓存。

## 8. 安全规范
- 🟢 Spring Security + JWT（密码哈希 BCrypt）；方法级 `@PreAuthorize`；资源归属校验（用户私有数据防越权，userId 必须匹配当前登录人）。
- 🔴【R9】SQL 注入：JPA 参数化禁拼接；XSS：输出转义；Token/密码/密钥禁入日志。
- 🔴【R9】`.env*`/`*.pem`/secrets 禁入库；依赖安全审计（npm audit / 后端依赖扫描）。

## 9. AI 集成规范（tea 特有）
- 🔴【R10】AI 请求必须走后端代理 `/api/v1/ai/*`，禁前端直连第三方 AI。
- 🔴【R10】降级链不可删：AI 不可用时回退规则引擎（前端 `teaAI.ts` 承重墙 + 后端 fallback 策略）。
- 🟢 Prompt 版本管理（`agent_prompts` 表 + 灰度）；输出 Schema 强校验（未知版本拒绝）。
- 🟢 AI 调用超时/重试/熔断；token 成本计量告警；敏感数据不入 prompt。

## 10. 日志与可观测性
- 🟢 统一 logback：级别（开发 DEBUG / 生产 INFO+）、模式含 traceId（MDC 贯穿请求）。
- 🟢 关键业务动作埋点（登录/品鉴提交/AI 请求）；指标用 Micrometer（错误率/延迟/缓存命中/AI token 消耗）。
- 🟢 禁打印请求体全文与敏感字段；日志必须可关联（traceId/userId）。
- 🟢 慢查询、AI 超时、降级触发必须告警（阈值与通道见 `开发流程规范.md`）。

## 11. 配置管理
- 🟢 配置分层：`application.yml`（公共）+ `application-{env}.yml`（dev/staging/prod）；禁硬编码。
- 🟢 敏感配置走环境变量 / `@ConfigurationProperties` 类型安全绑定；禁密钥写进 yml 提交。
- 🟢 配置变更走 PR 评审；生产配置与代码解耦（env_file / Vault 可选）。

## 12. 缓存规范
- 🟢 Caffeine 显式容量 + 过期 + 统计；Redis 键统一前缀 `tea:{module}:{business}:{id}`，必须设 TTL。
- 🟢 缓存与 DB 一致性：先写库再删缓存（或延迟双删）；禁无 TTL 的无界缓存。
- 🟢 穿透（空值缓存）/击穿（互斥锁）/雪崩（过期时间加抖动）防护；缓存内容与业务版本对应（Schema 变更即失效）。

## 13. 定时任务
- 🟢 `@Scheduled` 显式 cron/fixedDelay（禁 fixedRate 依赖执行时长）；任务方法幂等。
- 🟢 多实例部署用分布式锁（ShedLock）防重复执行；任务失败告警 + 重试有界。

## 14. 文件与上传
- 🟢 上传校验：大小上限、MIME 白名单、文件名安全（禁用户原始文件名直存，UUID 重命名）。
- 🟢 存储路径外置配置；下载接口鉴权（禁静态路径暴露给未登录用户）；头像/茶照片首版可延后。

## 15. API 设计
- 🟢 双栈并存：新栈 Spring Boot 统一 `/api/v1/{resource}`（见 `backend/src/main/java` 各 Controller）；旧 FastAPI `/api/{resource}` 仅维护不新增；破坏性变更引入 `/api/v2`，禁静默改已发布语义。
- 🟢 全局错误码表（`common/error-code/`）：错误码稳定、可查、不随文案变化。
- 🟢 分页契约统一（page/size，上限 size ≤ 100）；写接口幂等（client_id 头或字段）。

## 16. 测试规范
- 🟢 Service 纯逻辑单测（mock Repository 边界）；Controller 用 `@WebMvcTest`；只 mock 跨进程边界（网络/DB/时钟），禁 mock 内部协作者。
- 🟢 集成测试 Testcontainers PostgreSQL；迁移 upgrade/downgrade 往返测试。
- 🟢 命名 `given_when_then`；新增代码覆盖率 ≥ 80%，核心逻辑 100%。

# 二、前端规范（Vue 3.5 + TS strict + Pinia 4 + Tailwind 4 + TresJS + PWA）

## 17. Vue 组件
- 🔴【R11】Composition API + `<script setup lang="ts">`；禁 Options API；组件 ≤ 200 行（超了拆）。
- 🟢 Props/Emits 全类型；副作用在 onMounted/onUnmounted 管理；多词 PascalCase 命名。

## 18. 类型安全
- 🔴【R11】TS strict；禁 `any`、禁 `@ts-ignore`（特例需审批）；API 返回类型与后端 VO 对应。

## 19. 状态与数据流
- 🔴【R12】单向数据流：views → stores → services；业务状态走 Pinia（`src/stores/`），局部用 ref/reactive。
- 🟢 IndexedDB 统一 `src/services/storage/`；API 统一 `src/services/api/`。

## 20. 路由与权限
- 🟢 路由懒加载（`() => import(...)`）；路由守卫统一（登录态/角色）；404 兜底页。
- 🟢 敏感路由按角色校验（前端防呆，权限以后端为准）；动态路由（如需）有类型约束。

## 21. 表单与交互
- 🟢 表单校验与后端一致（schema 同源或规则对齐）；提交防抖/loading；失败保留输入 + 友好提示。
- 🟢 离线场景乐观更新（先写 IndexedDB 再同步，`sync_status` 流转）；操作反馈统一 toast/五态。

## 22. 错误监控与埋点
- 🟢 全局错误捕获（`window.onerror` / Vue `errorHandler`）上报；错误边界组件兜底。
- ⚪ 关键行为埋点（页面浏览/品鉴提交）与后端 traceId 关联；Web Vitals 可选上报。

## 23. 样式与设计令牌
- 🟢 Tailwind 4 工具类，禁自定义 CSS 文件（组件内 scoped 除外）；色值/间距/圆角/阴影走 `DESIGN_SPEC.md` 令牌，禁硬编码色值。
- 🔴【R13】设计门禁：改 UI 前先输出 Design Read（taste 三拨盘）；禁 AI 默认痕迹（Inter 默认/AI 紫渐变/三等分卡片/emoji 图标/玻璃拟态装饰）。

## 24. 3D（TresJS / Three）
- 🔴【R14】`src/components/three/` 只做视觉层，不改状态机（`3D_SPEC.md` 约束）。
- 🔴【R14】禁直接创建 renderer（统一 TresJS）；资源按需加载；KTX2 压缩纹理。

## 25. 离线优先与性能
- 🔴 离线降级链保留（`teaAI.ts` 承重墙禁删禁削弱）；视频不本地化。
- 🟢 懒加载/虚拟列表（大列表）；Core Web Vitals（LCP < 2.5s / INP < 200ms / CLS < 0.1）；`min-h-[100dvh]` 禁 `h-screen`。
- 🟢 构建体积：重型依赖路由懒加载 + 数据外置 + echarts 按需；`chunkSizeWarningLimit: 1000`（Three 单 chunk ~0.8MB 不可再拆，见 `vite.config.ts`）；`VISUALIZE=1` 出 `stats.html` 诊断。

## 26. 可访问性与边界
- 🟢 触控目标 ≥ 44px；状态五态齐全（hover/disabled/loading/error/empty）；对比度 ≥ 4.5:1。
- 🟢 键盘导航/焦点环/ARIA 语义；`prefers-reduced-motion` 降级；错误边界组件。

# 三、数据库规范（PostgreSQL + Flyway）

## 27. 迁移与回滚（核心红线）
- 🔴【R7】Schema 变更只走 Flyway：`db-migrations.sql` 成对存在，`.harness/changes/{feat-name}/` 含 `summary.md + db-migrations.sql + rollback.sql`，与 git 分支 `feature/{feat-name}` 同名。
- 🔴【R7】每个迁移必须可回滚：down 脚本成对，upgrade/downgrade 往返测试通过才可提交。
- 🔴【R7】禁生产 `ddl-auto: update`/`create`；禁手改已应用的迁移文件（追加新迁移，不修改历史）。

## 28. 模型与字段
- 🟢 表名 snake_case 复数、字段 snake_case；金额 `Integer`（分）、时间 `LocalDateTime`；软删除/审计字段/内部字段不外泄按 §5、§3 执行。

## 29. 命名与约束
- 🟢 索引 `ix_{table}_{col}`、唯一约束 `uk_{table}_{col}`、外键 `fk_{table}_{col}`，全部显式声明。
- 🟢 唯一约束覆盖幂等键（`client_id` + 用户维度）；CHECK 约束覆盖评分范围（0-100 / 工艺系数 0.5-2.0）。

## 30. 索引与查询
- 🟢 查询条件/外键/排序字段按需建索引（迁移脚本中显式声明）；分页 `Page<T>`，含条件分支时注意索引可用性。
- 🟢 批量操作用批量接口；慢查询（≥ 100ms）纳入告警（N+1、全表扫描判据见 §5）。
## 31. 性能与运维
- 🟢 连接池 HikariCP 显式上限（禁默认无界）；备份 pg_dump 每日 + 保留 14 天（`scripts/backup-postgres.ps1`）。
- 🟢 恢复演练定期执行；Schema 大变更（加列默认值/重建索引）评估锁表窗口，走预发验证。

# 四、部署规范（Docker Compose + 十阶段流水线）

## 32. 流水线门禁
- 🔴【R15】十阶段流水线（需求→方案→拆分→编码→单测→评审→集成→预发→部署→观测）**串行推进**：阶段 N 的 Quality Gate 未满足，禁入阶段 N+1。
- 🔴【R15】阶段 8-10 由 deploy-verify 承担：staging 验证（含冒烟）→ 部署脚本执行成功 + 冒烟通过 → 30 分钟观测期无异常。
- 🟢 小改动可合并阶段 1-3，但 `summary.md` 不可省略；红线检查与冒烟验证任何场景不可省略。

## 33. 部署单元与环境
- 🟢 `docker-compose.yml` 为部署单元（backend/frontend/postgres/nginx），环境变量外置（`.env.example` 只读参考）。
- 🟢 环境隔离：dev/staging/prod 三套 compose override；健康检查（`/actuator/health`）+ liveness/readiness 探针。
- 🟢 镜像标签规范（`git sha` 或语义版本）；生产部署前备份 DB + 确认边界。

## 34. CI/CD 门禁
- 🟢 CI 全绿（type-check + build + test + 迁移测试 + Compose 校验）才可 MR；阶段 6 评审通过且无 🔴。
- 🟢 构建产物校验（镜像可启动 + 冒烟）；生产发版走审批（发布窗口周二~周四）。

## 35. 回滚路线
- 🟢 回滚路线表（编码/单测/迁移/部署/观测五阶段 + 触发条件）见 `开发流程规范.md` §三，本文不重复维护。

## 36. 监控与告警
- 🟢 指标：错误率/延迟（P50/P99）/资源（CPU/内存/磁盘）/AI token 成本；观测期 30 分钟无异常才算完成。
- 🟢 告警通道明确（日志/指标/异常分类处理见 `开发流程规范.md` 与 trouble-shooting 技能）。

## 37. 分支与提交
- 🟢 分支命名、conventional commits（`type(scope): message`，subject ≤ 72 字符）、MR 门禁见 `开发流程规范.md` §二，本文不重复维护。
