# Expert Reviewer

## 触发
- 阶段 6 代码评审；MR 合入前（配合 .claude/agents/code-reviewer）。

## 工作流
1. 读变更清单（git diff + changes/summary.md），覆盖**全部变更文件**。
2. **两轴分开评，不合并也不互相掩盖**（代码合规但做错需求、或做对需求但破了规范，都是阻断）：
   - **标准轴**——6 维：正确性 / 性能（N+1/批量/缓存/分页）/ 安全（按下方 OWASP 清单）/ 一致性（wiki 漂移）/ 可维护性 / 架构合规（分层/红线）。可维护性只认启发式（命名不达意、重复代码、特性依恋、数据泥团、发散式变化、夸夸其谈通用性），启发式不得升为 🔴。
   - **规格轴**——对照 `summary.md` 的 F 编号与 Given-When-Then 逐条核对：①缺的或只做一半的 ②规格没要求却做了的（范围蔓延）③做了但实现走样。每条引 `summary.md` 原文行。
   - 无规格源（summary 缺 F 编号或未确认）→ 规格轴标「未验证」，不得标通过。
3. 分级输出：🔴 阻断（红线/安全/数据错误，禁降级）、🟡 主要（清零才过）、🟢 次要（记录）、🔵 提示（不阻塞）。
4. **每条 finding 附修复指引与规则出处（Harness 285「错误信息即 prompt」三要素，与 caveman-review 对齐）**：`FIX: <最短解法>` + `See: <红线编号/文档路径>`；🟡 以上必填，🔴 必须给。每轴正文 ≤400 字，只报本轴 finding，不排名跨轴优劣。
5. 收尾：评审记录落盘；🔴🟡 未清 → 回炉（三要素修复）→ 重评；**闭环 ≤2 轮**，第 2 轮仍不过 → 暂停人工介入。

## 安全维度（OWASP 分类，评审时逐项扫描）

- 注入（SQL / 命令 / XPath / LDAP）
- XSS（存储 / 反射 / DOM）
- 认证与会话（JWT 泄露、会话固定、弱哈希）
- 越权（IDOR 水平 / 垂直）
- 敏感数据暴露（脱敏、日志泄密、前端硬编码密钥）
- XXE / SSRF
- 不安全反序列化
- 日志注入（log forging）
- 依赖漏洞（CVE，对应 CI 的 npm/pip audit）

命中任一项 → 按 🔴🟡 分级处理（红线问题禁降级）。

## 红线
- 🔴 红线问题禁止降级；🟡 未清零不过评审；覆盖全部变更文件。
- **两轴不合并**：任一轴不通过即整体不过，禁止用另一轴的高分冲掉。

## 自检
- [ ] 标准轴 6 维全覆盖
- [ ] 规格轴逐条对过 F 编号与 GWT（无规格源已标「未验证」而非通过）
- [ ] 两轴分开报，无跨轴排名
- [ ] 🔴 零残留、🟡 清零
- [ ] 每条 finding 含 FIX 与规则出处（🔴 必须）
- [ ] 每轴正文 ≤400 字
- [ ] 评审记录已落盘（.harness/changes/{feat}/review.md）

## 下一步

评审通过 → 分支 push 开 PR 时写 `pr-body`（Summary + before/after 证据）→ 合并后 `deploy-verify`（部署验证）。
