# 会话交接标准化（session-handoff）

把"凭印象写交接"变成结构化、可校验的交接。本技能对应 `.harness/rules/开发流程规范.md` 第九节完成标准的"跨会话任务已更新 HANDOFF"，并把 AGENTS.md §13 四条交接血泪教训固化为硬门。

## 触发条件

- 会话即将结束（用户说"先这样"、"下次继续"、关窗口前）
- 上下文将爆（同一问题连续两次修正失败，AGENTS.md §2）
- 换 agent / 换机器 / 跨日继续
- 长任务切分完成一份切片，要交给下一个切片接手人
- 不触发：会话内继续推进、同 agent 同上下文、纯文档小改

## 前置条件（硬门，缺失回退）

- 当前工作区状态已确认（`git status --short`）
- 最近 commit 已实测（不是抄上一份交接的 hash）
- 已知阻塞项已亲自验证过当前状态（禁止继承上一份交接的"阻塞"结论）

## 命名与位置

- 文件：`docs/HANDOFF-YYYY-MM-DD-<suffix>-execution.md`
- suffix：同日多份用 a/b/c 递增；新一份在 frontmatter 写"本文件为最新交接，取代 docs/HANDOFF-...-b.md"
- 禁止覆盖旧交接（历史快照是审计证据）

## 长度硬限（用行数 + 字符数，不用字节）

**中文下字节/字符比约 2.15**，"≤4KB"折算仅约 1900 字符，与实际中位数（约 3900 字符）差一倍——两个维度不可兼得，用字节口径实测超标率 89%，成本全花在无意义达标上。改用：

- **交接文件：≤120 行、≤4000 字符。**
- 超限时优先动作：① 把"坑/打法"细节下沉到项目内检查清单/踩坑卡目录（卡片不设限），交接里只留一行指针；② 再压过程性叙述；**最后**才动措辞。**不砍数字与口径。**
- 压缩完**重新量** `len(字符)` 与行数，不凭手感。

## 禁止写（负面清单）

- 对话原文、聊天记录摘录
- 已读文件的内容复述（给路径即可）
- "某日做了 A、某日改成 B"式时间戳流水账
- "建议下一步继续推进"这类无信息空话
- 未经拍板的猜测（要写就标"待核实"）
- 对本次对话的指代（"上文提到的""如前所述"）

## /compact 机制（写检查点时必知）

- **同一会话内写文件本身不省 token**：历史消息不会因磁盘多了个 md 而消失。省 token 的唯一入口是压缩/清掉历史（`/compact` 斜杠指令，AI 无法代发，只能用户手动敲）。
- 所以检查点文件的角色是"**压缩的安全带**"，不是"上下文的替代品"。
- 分层用法：轻量对话 → 直接 `/compact`，不必写文件；重要任务（多文件/多口径/数字零误差）→ 先落盘检查点再压缩。
- 交接文件写完但**没给接手口令** = 对用户无效（用户不会去打开文件）。口令必须打在对话框里，单独成段。

## 强制结构（五段，缺一段不合格）

### 1. 一句话现状

一行说清"现在能干嘛、不能干嘛"。禁止用"差不多"、"基本完成"。

### 2. 仓库状态（带复核命令）

必须现场跑命令得到，禁止抄上一份交接：

```
- main = `$(git log -1 --format=%h)`（复核时间 YYYY-MM-DD HH:mm）
- 工作区：`git status --short` 原文贴
- 关键数字：<测试数/CI job 数/技能数>（复核命令：<npm run / mvn / node scripts/...>）
```

**铁律**：commit hash 必须带复核时间；超过 24 小时的交接，下一个 agent 接手第一件事就是重跑这三行。

### 3. 已复核断言 vs 未复核断言（分两栏）

| 已复核（怎么验的） | 未复核（下次先验） |
|---|---|
| 每条一行：`<断言> — <git log hash / 跑了什么命令 / 读了哪个文件:行号>` | 每条一行：`<断言> — <为什么是转抄的> — <下次第一步怎么验>` |

本会话有合并 PR 时，已复核栏优先用 **PR 表**（`<PR #> | <一句话内容>`）——真实 HANDOFF 的标准形式，比纯文字断言更可验。

**铁律**：
- 禁止在已复核栏里写"据上一份交接"、"之前跑过"——那是未复核。
- 三份交接叠加得到的"更全状态"是错觉；以本次实测为准（§13 教训）。
- 阻塞项不是断言，是一句待验证的假设——必须放进未复核栏，禁止直接写"阻塞：X"。

### 4. 下次第一步（具体到命令+文件）

禁止写"继续做 P0-3"这种裸编号。格式：

```
1. 跑：<具体命令，如 `npm run type-check`>
2. 读：<具体文件:行号>
3. 改：<具体哪个文件的哪一段>
```

**铁律**：跨文档引用编号必须带文档前缀——`docs/OPTIMIZATION_PLAN.md P0-3`，禁止裸 `P0-3`（§13 教训：裸编号在三份文档指三件事）。

### 5. 关键设计决策（防重做）

- 本会话推翻的旧决策
- 承重墙约束（动了会回归的点）
- 一次一行，引用 ADR 编号不复制正文

## 纪律

- **只写指针，不复述长内容**：引用文件路径+行号，不要把 summary.md 整段抄进 HANDOFF。
- **敏感信息脱敏**：禁止写 API key / token / 密码 / 用户数据；引用 `.env*` 用占位符。
- **决策点列清楚**：等用户拍板的事单独列，不要埋在叙述里。
- **本会话自查更正也要记**：发现自己之前说错了什么，写在"自查更正"节，不要掩盖。
- 旧交接的"一句话现状"与本份冲突时，以本份为准；旧文件保留不删。

## 检查清单（写完逐项过）

- [ ] frontmatter 齐（name/description/status/date/last_updated/owner）
- [ ] 一句话现状无"差不多/基本"
- [ ] main hash + 复核时间 + 复核命令现场跑过
- [ ] 已复核/未复核分栏，无"据上一份交接"字样
- [ ] 阻塞项全部进未复核栏，带下次验证方法
- [ ] 下次第一步具体到命令+文件，无裸编号
- [ ] 跨文档编号带文档前缀
- [ ] 无密钥/token/用户数据
- [ ] 旧交接已在 frontmatter 标注被取代

## 下一步

- 把 HANDOFF 文件路径贴给用户，提醒"新会话第一句：读这份 + TODO-PRIORITY + 对应 PLAN"。
- 下一个 agent 接手时，先重跑"仓库状态"三行命令，再读未复核栏。
