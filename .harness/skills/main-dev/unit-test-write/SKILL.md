# Unit Test Write

## 触发
- 进入阶段 5 单元测试；新增/修改逻辑必须带测试。

## 工作流
0. **写码前先定测试范围**：和用户确认优先测哪些行为——**不能测全部**，聚焦关键路径与复杂逻辑，不是每个 edge case 都写。测试行为清单（不是实现步骤）先列，用户点头再写。
1. **TDD 优先**：先写一个失败测试 → 最小实现让它过 → 下一个（垂直切片，禁水平切片）。
2. **技术栈**：
   - 后端：JUnit 5 + Mockito；Controller 用 `@WebMvcTest`；Service 纯逻辑单测（mock Repository 边界）；集成测试 Testcontainers PG。
   - 前端：Vitest；组件测试（Props/Emits/五态）；composable 测试。
3. **用例顺序**：正常路径 → 边界值 → 异常路径 → 幂等 → 状态流转。
4. **行为测试三规则**：只走公共接口；不 mock 内部协作者（只 mock 网络/时钟/DB 驱动）；重构不改测试。
5. **重构纪律**：**Never refactor while RED**——必须先全绿（GREEN）再动重构；每次重构后跑测试。
6. **收尾**：覆盖率 ≥80%（核心逻辑 100%）→ 测试全绿。

## 自检
- [ ] 测试范围已和用户确认（不是每个 edge case 都测）
- [ ] TDD 垂直切片（先红后绿，未在 RED 状态重构）
- [ ] 正常/边界/异常/幂等/状态 用例齐全
- [ ] 覆盖率 ≥80%，核心 100%
- [ ] 全绿无跳过
