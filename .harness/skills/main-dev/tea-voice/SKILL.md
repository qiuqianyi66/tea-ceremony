# tea 声音（tea-voice）

tea 面向用户的**所有文字**（传播文案 / README / 官网 / UI 文案 / CHANGELOG）须听起来像**一个人做的安静小项目**，不像营销稿。本技能的音准来自项目自己的文案：**`docs/promotion/posts.md` 是唯一范本**，改文案前先读它。

## 触发条件

- 写/改 `docs/promotion/` 下任何平台的文案
- 写/改 `README.md`、官网静态文案、`CHANGELOG.md` 的用户可见段落
- 写 UI 里的文案（按钮/空态/引导语/分享卡文字）
- 不触发：代码注释、内部技术文档、commit message、给用户的技术解释

## tea 声音四特征（从自己的文案反推，不是通用规则）

**① 短句成段，一段一句。**
范本："不是科普，不是工具，是一个能坐五分钟的地方。" 一句一个意思，句号收尾，不写长复合句。

**② 正反对照定义法。**
范本："不是茶文化百科，不是计时器，是一个能坐下来泡一杯茶的小茶室。"
先说**不是什么**（划掉两个最容易被误认的），再说**是什么**。这是 tea 定义自己的标准句式，新文案尽量沿用。

**③ 动词主导，具体名词收尾。**
范本："选茶 → 煮水 → 注水 → 出汤""蒸汽会起来，汤色会变深"。
用动作和看得见的东西说话（蒸汽/汤色/桌面/二维码），不用抽象名词（体验/赋能/价值）。

**④ 低音调，不吆喝。**
范本："I'm still learning""deliberately quiet""Would love feedback"。
不喊"最强/颠覆/革命性"，不承诺效果。不确定就说"还在学"。**tea 的气质是安静，文案不能吵。**

## AI 味扫描（写完逐条扫，命中即改）

来源 humanizer（16 条）的**中文高发子集**，按 tea 语料频次排序：

1. **em dash 滥用**：`—` 连用或一段多个。中文改用逗号，或直接断句。
2. **三连排比**：三个形容词/短语堆叠（"快、准、稳"）。删到两个或改成一个具体事实。
3. **空洞升华**：`不仅是…更是…`、拔高到"时代/未来/意义/旅程"。直接删这句。
4. **虚假范围**：`从 X 到 Y` 里 **Y 是空话或与 X 不同维**（"从选茶到美学境界"，选茶是动作、美学境界是感受）。若 X→Y 是**同一维度的真实连续步骤**（"备器→煮水→醒茶→冲泡"）则是好写法，**保留**。
5. **模糊归因**：`业内认为` / `研究表明` / `众所周知` 无出处。要么给来源，要么删。
6. **同义换词**：同一个东西前后叫不同名字（茶室/茶空间/茶间）。**同物同词**（AGENTS.md §2 ③）。
7. **粗体与标题滥用**：一段里多处 `**…**` 抓眼球。一段最多一个强调。
8. **`-ing` 式浅分析**（英文帖）：`..., ensuring ...` / `..., making it ...` 这类收尾。删掉，或改成独立短句。

## 流程

1. 读 `docs/promotion/posts.md` 对应平台那一版（范本 + 已有语气）。
2. 按**四特征**写或改。
3. 逐条跑**AI 味扫描**。
4. 交付前问一句：**"这话像我坐下来泡茶时会说的吗？"** 不像就改。

##  Discipline

- **不改范本的立场**：tea 主动说"不是百科、不是工具"是刻意的定位表达，不是可优化的修辞，别"帮它说得更全面"。
- 中英文不互译：英文版（Reddit/HN）是**按英文社区重写**，不是中文直译。
- 本技能只管对外文本；给用户的技术解释走 AGENTS.md §2 写作风格，不套 tea 声音。
