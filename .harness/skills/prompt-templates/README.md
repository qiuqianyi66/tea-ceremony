# prompt-templates-skill 总览（提示词模板，4 个）

> 加载方式：本表定位 → Read 1 个 SKILL.md → 仅正文点名的 references/assets/scripts 才读（禁预读）；细则见 `.agents/skills/README.md` §加载方式。
> 第 4 族：**提示词模板族**。前三族（main-dev / biz-dev / trouble-shooting）是「模型照着做的流程」；本族是「写给模型看的提示词」——产出物是一段可直接复制的 prompt，不是代码、不是评审意见。

## 调用规则

- **本族不执行任务**：触发后只产出提示词，把提示词交给主模型（或另一个会话）执行。
- **执行阶段的路由不变**：拿到提示词开始干活后，仍按 `.harness/skills/main-dev/README.md` 的阶段路由表走（阶段 4 → coding-skill，阶段 5 → unit-test-write）。
- **一场景一模板**：不要在一个提示词里同时要「开发 + 审查 + 性能」。混装会让模型在每个维度都做浅。
- **模板可裁剪不可自创维度**：审查固定六维、排查固定六阶段、性能固定「先测再改」；裁剪的是占位符，不是纪律。
- **交叉审查用同一提示词跑两遍**：同模板交给两个模型，比对发现差异，比「让一个模型更努力」有效。
- **提示词里禁不可判定词**：`尽量 / 适当 / 合理 / 优化一下` 一律换成可观察条件。

## 使用步骤

1. 按场景从上表选技能，Read 对应 `SKILL.md`。
2. 复制「模板 A」（完整场景）或「模板 B」（轻量 / 特定场景）。
3. 填占位符：`{{…}}` 全部替换，没有的写「待确认：X」，不许留空。
4. 核对模板底部的检查清单（每份 SKILL.md 末尾都有）。
5. 把提示词交给执行者；执行者按 `AGENTS.md` §4 流程干活并交验证证据。

## 与其它族的分工

| 族 | 是什么 | 何时用 |

| main-dev（14） | 十阶段流水线的各阶段做法 | 已经在干活，需要某阶段的具体规范 |
| biz-dev（19） | 后端 / 数据 / AI 能力的领域规范 | 动后端、数据库、AI 链路 |
| trouble-shooting（6） | 故障定位与专项排查 | 已知问题类型，需要排查路径 |
| **prompt-templates（4）** | **写给模型的提示词** | **要把任务外包给另一个模型 / 会话，或要可复用的标准问法** |
