# 功能开发提示词（feature-dev）

功能开发场景的可复制提示词。**本技能只产出提示词，不执行编码**；执行由拿到提示词的模型按 `AGENTS.md` §4 流程走。

## 触发条件

- 用户要开新功能 / 新页面 / 新接口，希望拿到一段可复用提示词，而不是一次性对话
- 需求还含糊（无验收标准、无范围边界），需要先逼出 F 编号 + Given-When-Then
- 同一提示词要交给不同模型 / 不同会话复用

不触发：改文案调样式（走 Fast 轨道直接做）、修单点 bug（走 `debug-issue`）、审查已有代码（走 `code-review`）。

## 前置条件（硬门，缺一条就先补齐再发提示词）

1. 已读 `AGENTS.md`（规则全量常驻），知道 §4 流程与 §5 改动纪律。
2. 已知目标模块路径（`src/views/…` / `src/services/…` / `backend/…`）；不知道就写「待确认：模块路径」占位，不许猜。
3. 环境可跑（`npm run dev` 起得来）；提示词要求模型真跑验证命令，环境不可跑会退化成立即猜测。
4. 已判定改动级别（L0 文档 / L1 UI / L2 逻辑 / L3 架构），据此选模板 A 或 B。

## 模板 A：完整功能（Guided / Controlled 轨道）

````text
你是「一盏茶」项目的编码助手。任务：{{功能一句话}}。

## 项目上下文
- 技术栈：Vue 3.5 + TS(strict) + Pinia + Tailwind 4 + Vite；后端 Spring Boot 3.5（重写中）
- 规则源：AGENTS.md（不可妥协 / 改动纪律 / 前端规范）——与其他文档冲突时以它为准
- 设计基线：DESIGN_SPEC.md（色令牌 var(--color-*)、圆角 sm/md/xl/2xl、触控 ≥44px）
- 目标模块：{{模块路径}}；相关文件：{{文件清单}}
- 同类现有实现（照抄风格，不另立新规）：{{参考文件}}

## 需求（先补全再动手，缺项就停下来问）
- F-01 {{功能点}}：Given {{前置}} When {{动作}} Then {{可观察结果}}
- F-02 …
- 范围边界：本次做 {{…}}；本次不做 {{…}}
- 影响面：{{路由 / store / service / 数据库 / 3D}}

## 硬约束
1. `<script setup lang="ts">`；禁 any；组件 ≤200 行；样式只用 Tailwind（不写 <style> 块）
2. 颜色 / 圆角 / 阴影只用 DESIGN_SPEC 令牌，禁裸色值；图标用 lucide 全局组件 IconXxx，禁 emoji
3. 五态齐全：hover / disabled / loading / error / empty
4. 只动必须动的：不改无关文件、不新增依赖、不顺手重构跑得好的代码
5. AI 请求必须走后端代理 /api/v1/ai/*，禁浏览器直连第三方

## 执行流程（按序，不许跳）
1. 开工自查：`git log --oneline -10` 确认该功能未实现；已实现则补缺验证，禁从零重写
2. 拆解：现状（实测）→ 根因/缺口 → 子问题清单 → 待验证项
3. Mini Plan：目标 / 步骤 / 影响文件 / 验证方式。超过 3 个文件或涉及架构 → 先给方案等确认
4. TDD：先写失败测试（只打公共接口，不 mock 内部协作者）→ 最小实现 → 重构
5. 验证命令链（真跑并贴输出）：
   `npm run type-check && npm run test && npm run lint && npm run build`
   动了 3D / 冲泡流程再加：`node scripts/verify-gardens.cjs`
6. 报告：改动清单（文件 + 行号）/ 验证证据 / 未覆盖项与原因

## 输出格式
- 先给 3 行以内的计划，再给代码
- 代码块标注文件路径
- 结尾分「已验证 / 未验证」两栏列证据；没跑过的命令不许写成跑过
````

## 模板 B：轻量改动（Fast 轨道，单文件低风险）

````text
在「一盏茶」项目里做一处小改动：{{改动一句话}}。
文件：{{单个文件路径}}。
约束：Tailwind + DESIGN_SPEC 令牌、不改其他文件、不新增依赖。
先读该文件与调用它的地方，再改。改完跑 `npm run type-check && npm run build`。
输出：改了什么（行号）+ 命令真实输出。
若发现改动会波及 {{X}}，停下来先问，不要自行扩大范围。
````

## 占位符对照

| 占位符 | 填什么 | 反例 |
|---|---|---|
| `{{功能一句话}}` | 用户可见的结果 | 「优化一下体验」 |
| `{{模块路径}}` | 具体到目录 | 「前端」 |
| `{{参考文件}}` | 同层同类的现有实现（先 ls 确认存在） | 「找个类似的」 |
| `{{…}}` 范围边界 | 明确写出不做什么 | 留空 |

## 检查清单

- [ ] 每个 F 编号都有 Given-When-Then，Then 可观察（不是「更流畅」）
- [ ] 范围边界含「本次不做」
- [ ] 参考文件真实存在（写进提示词前先确认路径）
- [ ] 验证命令从 `package.json` 抄，不凭记忆
- [ ] 提示词里没有「尽量 / 适当 / 合理 / 优化一下」这类不可判定的词
- [ ] 需求有两种合理解读时，模板保留「先问再动手」，不替用户选
- [ ] 改动级别与模板匹配（L1 用 B，L2/L3 用 A）
