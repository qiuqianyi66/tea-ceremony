# 性能问题提示词（performance）

性能优化场景的可复制提示词。**本技能只产出提示词**；纪律是「先测 → 再改 → 再测」，无基线不动手。

反面模式（本技能要防的）：凭感觉加 `memo` / 加缓存 / 拆组件，改完不知道快了没有。

## 触发条件

- 用户报「卡 / 慢 / 首屏白屏久 / 滚动掉帧 / 内存一直涨」
- 要优化某个具体指标（LCP、INP、CLS、接口 P95、构建体积）
- 优化过一次但说不清收益（没有前后数据）

不触发：功能没做完就谈性能（先 `feature-dev`）；线上故障排查（走 `debug-issue`）；纯代码风格（走 `code-review`）。

## 前置条件（硬门）

1. 有可量化的指标口径：哪个页面 / 哪个接口 / 哪个百分位（P50 还是 P95）。
2. 有可重复的测量方法：同设备、同网络、同数据量、同缓存状态。
3. 有基线数字（改之前先测一次并留档），没有基线就先测，不许跳过。
4. 知道优化预算：允许改架构吗？允许加依赖吗？允许改数据模型吗？

## 分诊：先判是哪一类瓶颈

| 症状 | 大概率瓶颈 | 首选手段 |
|---|---|---|
| 首屏慢 / 白屏久 | 包体积、阻塞渲染的资源、字体 | 构建分析 + 资源拆分 + 预加载 |
| 交互卡顿 / 掉帧 | 长任务、同步计算、逐帧更新 | Performance 面板找长任务，拆 rAF |
| 接口慢 | 慢 SQL、N+1、串行调用 | `EXPLAIN` + 合并/并行请求 |
| 内存涨 | 监听器/定时器未清、无界缓存 | 堆快照对比 |
| 3D 场景卡 | 三角面数、材质数、阴影分辨率 | 降级策略 + 实例化 |

## 模板 A：前端性能

````text
你是「一盏茶」项目的性能优化者。目标指标：{{指标}}（{{页面/接口}}，目标值 {{目标}}）。

## 铁律
先测基线，再定位，再单变量改，再复测。没有基线数字不许动手改代码。

## 步骤
1. 基线测量（留档：命令 + 数字 + 环境）
   - 首屏/交互：`npm run build && npm run preview` 后用 Lighthouse 跑同一页面，记录 LCP / INP / CLS
   - 运行时：Performance 面板录 5 秒操作，导出主线程长任务（>50ms）清单
   - 包体积：`npm run build` 看产物 + 用 visualizer 找前 5 大模块
   - 已有自测口径：`src/services/vitals.ts` 上报的 web-vitals 数据
2. 定位热点：只列证据（火焰图 / 长任务 / 大模块），不列猜测
3. 假设 + 单变量优化：一次只改一处，写清「预期这个改动让 {{指标}} 下降 {{X}}」
4. 复测：同环境同步骤重测，给前后对比表
5. 若收益 < 5%，回退该改动，不做「留着也许有用」的优化
6. 记录：瓶颈 / 改动 / 前后数字 / 是否引入复杂度债

## 约束
- 不改业务行为；改动必须可回滚（单独 commit）
- 不加新依赖除非有实测收益且写明「否掉自研的理由」
- 3D 相关改动先读 3D_SPEC.md，禁绕过 TresJS 生命周期
- 优化后跑：`npm run type-check && npm run test && npm run build`

## 输出格式
| 阶段 | 指标 | 改动前 | 改动后 | 结论 |
结尾给：保留的改动清单 + 回退的改动清单 + 未解决瓶颈与原因
````

## 模板 B：接口 / 后端性能

````text
接口 {{METHOD /path}} 慢：当前 P95 {{X}}ms，目标 {{Y}}ms，数据量约 {{N}} 行。

1. 复现：给出可重复的压测命令（{{wrk / ab / 脚本}}），固定并发与数据量，测 3 次取中位
2. 定位：`EXPLAIN (ANALYZE, BUFFERS)` 看真实执行计划；查 N+1（一次请求的 SQL 条数）、
   串行远程调用、缺索引、全表扫描、大字段无谓 SELECT *
3. 单变量改：加索引 / 改查询 / 合并请求 / 加只读缓存，一次一个
4. 复测：同命令同数据量，给前后 P50/P95 对比
5. 检查副作用：写入路径是否变慢、缓存一致性、事务边界（禁事务内远程调用）
6. 结论：收益 <10% 的回退；保留的改动写进 ADR 或注释说明「为什么加这个索引」

约束：不改 API 契约（改契约先走需求分析）；迁移脚本成对（upgrade + rollback）。
````

## 检查清单

- [ ] 提示词要求先出基线数字，且要求同环境复测
- [ ] 指标口径明确（页面 / 接口 + 百分位 + 数据量）
- [ ] 要求单变量改动，禁止一次改五处然后说「快了」
- [ ] 要求收益阈值（<5% 前端 / <10% 后端回退），防止留下复杂度债
- [ ] 要求前后对比表，不接受「感觉快了」
- [ ] 要求跑 type-check / test / build，防止优化把功能改坏
- [ ] 3D / 数据库相关先指到 `3D_SPEC.md` 与迁移规范
