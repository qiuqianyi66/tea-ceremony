- **多会话并行共享一个 worktree：`git push` 前必须显式确认分支，禁裸 push（2026-10-19 一天内实测两次）**：第一次，我在 `fix/ai-hide-retrieval-state` 上 commit 后仅 5 秒，并行会话在同一工作区连续提交两次（`.env.example` / `vitals.spec.ts`）把 HEAD 推走——它 checkout 自己的分支前，HEAD 恰好停在我的分支上，`git commit` 就直接落进了我的分支。第二次，手动 push 时发现工作区已被切到 `fix/experiment-trace-attribution`（且带自己的 upstream），若用裸 `git push`，推上去的会是别人的实验追踪工作，自己的修复一个都上不去。铁律：**push 前必须 `git branch --show-current` 显式确认，并 `git push -u origin <分支名>` 显式指定**；**验证提交要用 `git show --stat <hash>` 按 hash 验，不能用 `git log --oneline -1`**——后者在并发下几秒内就会变成别人的提交，会误判成"我的提交丢了"。
- **改用户可见文案必须同步评测判分契约，CI 全绿发现不了这类回归（2026-10-20，#122 的后置修复）**：#122 把「知识库未命中，以下为常识回答」从用户可见回复中摘掉（改为「以下为茶路常识，未引自站内文献。」），`mvn test` 506 run / 0 fail、13 项 CI 全 pass。但 `docs/ai-eval/cases/librarian.yaml` 的 LIB-006 有 program 考点「未命中时明示常识回答」，`eval-core.cjs` 用 `hasAny(text, ['未命中','常识回答'])` 做**字面匹配**——新文案两个子串都不含，该考点必然判 0。而这个判分分支**恰好没有任何 node-test 覆盖**，所以 Java 单测、CI、PR 检查没有一道门发现它。铁律：**改对外文案/响应格式后，必须 grep 评测用例定义与判分函数里的同款字面串**（评测契约是 CI 之外的第三套断言，Java 测试绿不代表它兼容）；判分关键词表要同时接受新旧表述，并配回归测试锁死。
