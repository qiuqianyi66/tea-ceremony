# plan-control — 人读审查页

> 面向人的审查页。模型执行规则见 `.agents/skills/plan-control/SKILL.md`。

## 它管什么

Agent 的复杂任务控制协议：决定 **何时该停下先规划 / 何时该问人 / 何时可以直接执行**，以及方案怎么审批、执行怎么验证、完成怎么证明。

**定义性约束**：它是控制协议，不是运行时。状态机、事件总线、调度、持久化、审计存储、可观测指标属 Agent OS Runtime V5，**不应被塞进本技能**。

## 何时该用 / 何时不该用

**该用**：用户说「/plan」「先出方案」「规划一下」「别急着做」「给个方案确认后再做」；或任务涉多文件 / 架构选择 / 高风险（删除、迁移、数据修改、生产或外部影响）/ 需求含糊或多种合理方案。

**不该用**：纯问答、解释说明、文档阅读、明确步骤执行、小范围低风险修改（走 Fast Path）。

## 审查要点（人过一遍时核对）

- [ ] 该停下问人的场景，是否真的停下出了方案（而不是闷头干完）
- [ ] 风险评分四维（Impact / Scope / Uncertainty / Irreversibility 各 0-3）是否如实，没有为了省事压低风险
- [ ] 审批分级（Always / Batch / Auto）是否被执行——Always 级有没有真的等人确认
- [ ] 执行过程中是否做了漂移检测（方案被改时是否停下来重新确认）
- [ ] 完成时是否带四层验证证据，而不是"我觉得没问题"
- [ ] 失败恢复是否走七类流程，而不是简单重试掩盖
- [ ] 架构级选型是否写了双向论证（选 A 理由 + **否 B 理由** + 反转条件），而不是只写"为什么选 A"
- [ ] 选型理由里有没有出现"业界都这么做 / 主流方案"当唯一论据（那是同质化偏见，不算理由）
- [ ] 有没有命中 §9.2「反过度设计警示」却没解释（如给固定管线套动态编排、为不存在的第三方建插件机制）
- [ ] 反向检查：状态机 / 事件 / 调度 / 持久化等运行时职责**没有**被写进技能

## 怎么知道它在生效

- 复杂任务的第一回应是方案（含风险分级与批准门），不是直接动手
- 高风险动作前有人工确认点，且确认点与风险分级一致
- 最终交付附带可核对的验证证据
