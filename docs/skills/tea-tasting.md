# tea-tasting — 人读审查页

> 面向人的审查页。模型执行规则见 `.agents/skills/tea-tasting/SKILL.md`。

## 它管什么

一盏茶的**可解释冲泡-品鉴模型**：八维口感评分 × 冲泡工艺系数 = 最终评分；六大茶类冲泡参数基准；品鉴记录离线同步语义。

**定义性约束**：评分必须能用人话解释为什么。禁止用神经网络或复杂加权公式替代当前可解释模型（黑盒）。

## 何时该用 / 何时不该用

**该用**：修改评分逻辑、冲泡参数、添加新茶类、改品鉴相关代码（含离线同步）。

**不该用**：与品鉴/冲泡无关的常规 UI 或业务改动。

## 审查要点（人过一遍时核对）

- [ ] 评分公式仍为「八维平均分 × 工艺系数（0.8-1.2）」，未引入黑盒模型
- [ ] 八维维度（汤色/香气/滋味/苦涩/生津/喉韵/耐泡度/协调性）未随意增删
- [ ] 茶类冲泡参数符合常识基准表（绿茶 80-85°C、乌龙 95-100°C 等），无编造数字
- [ ] 修改评分逻辑后，**已有品鉴记录评分不变**（评分在记录创建时计算并存储）
- [ ] 极端参数验证过（水温过低/过高、时间过短/过长）
- [ ] `sync_status`（pending/synced/failed）语义未被破坏；同步失败保留本地数据
- [ ] 茶文化内容无编造，不确定处标「待核实」，优先用 `src/data/` 已有数据

## 怎么知道它在生效

- 选茶 → 冲泡 → 品鉴记录全链路在新茶类/新参数下可用
- 品鉴卡评分与手算公式一致（抽查可复算）
- 离线创建记录后，网络恢复自动补同步
