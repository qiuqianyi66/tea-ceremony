# ADR-013：引入 pgvector + pg_trgm 混合检索（S2 知识检索升级）

- **Status**: Accepted
- **Date**: 2026-10-07
- **Supersedes**: 无（新增决策；S1 的 4 表 ILIKE 检索保留为降级路径）

## Context

S1 知识问答（librarian）用 `CultureSearchService` 对 4 张文化表跑 `ILIKE '%关键词%'`。两个缺陷：

1. **语义召回为零**：问"茶圣是谁"匹配不到"陆羽"（字面无关）；同义词/别名（"茶中皇后"→"君山银针"）全部漏召。
2. **覆盖只有一半**：知识库 8 张文化表（teas/tea_people/tea_regions/tea_poems/teawares/tea_etiquettes/tea_relations/tea_processes），RAG 仅用 4 张——茶器/茶礼/关系图谱/制茶工艺缺席。

知识库规模百条级（teas 66 条实测），embedding 成本可忽略。基础设施为 PostgreSQL 16（docker-compose `postgres:16-alpine`），pgvector 为同库扩展。

## Decision

**混合检索（hybrid search）**：pgvector（语义）+ pg_trgm（关键词精确）双通道，同一次查询合并排序。

1. **引擎**：docker-compose db 镜像 `postgres:16-alpine` → `pgvector/pgvector:pg16`（同 PG16 大版本，pgdata 卷兼容，数据不丢）。
2. **迁移**：Flyway V2 建扩展（`vector` + `pg_trgm`）+ `culture_chunks` 表（chunk_text + `vector(1024)` + metadata 过滤 + status 驱动回填）+ HNSW 向量索引 + GIN trigram 索引。
3. **切块**：按实体切（8 表各条目一源一块，uk(source_type, source_id)），metadata 存茶类/朝代/产区供过滤。
4. **Embedding**：阿里云百炼 `text-embedding-v3`（与 DashScope 同 key，维度对齐模型输出，实现时登记）。
5. **降级**：embedding 服务不可用 → 自动降级纯 pg_trgm/ILIKE（检索不中断，S1 行为保留）。
6. **覆盖**：CultureSearchService 扩至 8 表（兑现"知识面 +75%"），检索清单可配置。

## Consequences

- docker-compose.yml 的 db 服务镜像变更（`pgvector/pgvector:pg16`）；CI migration-test 的 postgres 服务镜像同步更新。
- Flyway V2 迁移 + rollback 成对（.harness/changes 模板）；Testcontainers 集成测试自动验证 V2 up。
- librarian 检索路径升级为混合检索；S1 的 ILIKE 保留为降级分支。
- 回填任务：8 表增量生成 chunk + embedding（S2 实施，依赖 AI key 就绪；无 key 时表空但结构就绪）。
- 独立向量库（Milvus/Qdrant）**不引入**：十万级/多租户才需要，当前是纯运维负担。

## Rejected

- **维持纯 ILIKE（S1 现状）**：语义零召回 + 8 表覆盖不足，无法支撑"茶灵"体验差异。
- **独立向量库（Milvus/Qdrant）**：知识库百条级，独立部署/监控/备份成本远大于收益。
- **纯 pgvector（去关键词）**：精确词（茶名/人名）字面命中是用户高频诉求，关键词通道必须保留。
- **引入时无真实场景**：chunk/检索/回填三链路均有真实代码路径与测试，非摆设式引入。
