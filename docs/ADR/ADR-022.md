# ADR-022：匿名遥测上报（部分取代 ADR-006）

- **Status**: Proposed
- **Supersedes**: ADR-006 的「错误与性能指标不上报」部分（行为埋点 `trackingEvents` 仍保持纯本地）
- **Related**: ADR-021（无 Redis）、ADR-016（评测底座）

## Context

ADR-006 规定埋点、错误缓冲、Web Vitals 全部只写 IndexedDB，不上报后端。该决策带来一个已实测的运行后果：

1. 线上站点 `http://42.121.125.4` 首屏 LCP 实测 5.8–6.3 s，`/health` 页因调用不存在的 `/api/health` 永久显示「后端不可达」，两者都**在客户端可见、在服务端不可见**。
2. `src/services/errorBuffer.ts` 与 `src/services/vitals.ts` 采集的数据只存在于用户自己的浏览器里。用户不主动导出，运维侧拿不到任何样本。
3. 因此「系统评估体系与稳定性兜底」在当前架构下无法成立：没有数据源，就没有分位统计、没有 SLO、没有错误预算、没有回归基线。

ADR-006 的隐私理由依然有效：不能因为要观测就采集用户内容。所以本决策不推翻隐私边界，只推翻「传输」这一条。

## Decision

新增**匿名遥测上报通道**，与既有本地存储并存：

1. **上报内容限于三类结构数据**：脚本错误（消息/堆栈/文件行号）、Web Vitals 五指标、错误指纹。不含用户输入、茶名、品鉴文本、账号标识。
2. **身份只有随机 UUID**：`clientId`（设备级，用户可在设置页重置）与 `sessionId`（会话级）。不关联 `user_id`，不落 IP，不落 UA 原文。
3. **错误消息脱敏后入库**：剥离 URL query、邮箱、JWT/长 token 形态串、纯数字 ID。
4. **多级兜底传输**：`sendBeacon` → `fetch(keepalive)` → 普通 `fetch` → IndexedDB outbox 指数退避重试；连续失败开熔断，熔断期只入队不发。
5. **服务端幂等**：`client_event_id` 唯一约束去重，重复上报计数不累加。
6. **行为埋点 `trackingEvents` 保持纯本地**（ADR-006 该部分继续有效），因为其价值在「茶灵去留」的本机决策，外发无收益。
7. **用户可关闭**：设置页提供遥测开关，关闭后采集与上报同时停止。

## Consequences

- 服务端获得真实样本：可算 P75 分位、SLO 达成率、错误预算、错误指纹聚合与首次出现告警。
- 新增三张表（`telemetry_events` / `error_fingerprints` / `slo_snapshots`），需保留策略防止无界增长：raw 事件保留 7 天，指纹与快照永久。
- 新增攻击面：`POST /api/v1/telemetry/batch` 为匿名可写端点，必须挂限流与体积上限，且不做任何回显。
- 前端首屏 JS 增加约 3 KB（gzip 后），换取可观测性；采集逻辑全部异步，不阻塞渲染。
- 若将来接入 Sentry 等商业方案，本通道可退化为出口，表结构不必改。

## Rejected

- **接 Sentry / Datadog**：违反离线优先与零第三方数据出境，且免费额度对个人项目不够；自建通道成本更低。
- **只做服务端日志**：拿不到 RUM 的 LCP/INP（真实用户指标必须在浏览器侧采集），也拿不到前端异常堆栈。
- **全量本地导出人工收集**：无法自动化，无法形成 SLO 趋势，实测已证明运维侧永远看不到。

## 反转条件

出现下列任一情况，重新评估本决策：
- 引入需要登录才能观测的多租户，匿名通道无法归因；
- 监管要求数据不出境或不得采集任何客户端指标；
- 自建通道的运维成本（迁移/保留/告警）超过团队承受力。
