# ADR-019：任务控制协议上收至最高规范（分诊 / 拆解 / 客观执行）

- **Status**: Accepted
- **Date**: 2026-10-10
- **Supersedes**: 无（扩展 ADR-009 定义的 AI Change Protocol）

## Context

ADR-009 把 AI Change Protocol 定为五步（理解上下文 → 确认影响范围 → 修改 → 运行验证 → 报告证据）。该协议运行至今暴露三类缺口，均由实测证据触发：

1. **继承未复核的断言当事实**。A4「cu 虚拟桌面占用」被连续多份交接记为唯一阻塞项，卡住 K23 截图 / P0-3 验收 / v3 Judge 实跑三项。实测全部不成立：截图脚本自带 `ensure-dev-server.cjs`（5173 自动拉起），`verify-*3d*` / `verify-pavilion` / `verify-gardens` / `verify-icons` 全 ERRORS: []，三个截图脚本 exit 0，`eval-tea-ai.cjs --judge` 出全量分。**断言在转抄中升级成事实**，无人实测。
2. **交接快照被叠加使用**。三份并行交接分别自称 main = `b9f083a` / `137b3a5` / `b9f083a`，实为三张不同时刻的快照。实测抓出 6 处硬错（A4 阻塞假、"后端重写已完成"假、测试数 201 实为 211、`chore/pr-flow-rule` 称未推送实已合、`tea-testing` worktree 称存在实已无、v2 0.96 当成果实为 program-only 口径）。commit 哈希 14 个全部真实——**问题不在编造 ID，在结论层不加复核地转抄**。
3. **未拆解直接开工 / 流程深度与任务不匹配**。复杂需求常直接进编码；同时小改动又要走全套十阶段，成本错配。

同时存在一处编号治理缺陷：`P0-3` 在三份文档指三个不同事项（前端返工 / AI key / PWA prompt），交接转述会造成实质误工。

## Decision

在最高规范 `AGENTS.md` 固化四项任务控制，并**只做接线、不抄技能正文**：

1. **§0 第 6 条「客观执行」**：结论以实测为准，不以记忆、推断、上一份交接为准；无法实测的必须标注「未复核断言」，禁止当事实转抄。
2. **§0 第 7 条「先拆解、再动手」**：先拆成子问题（现状 → 根因 → 子问题清单 → 待验证项）；需求过 `request-analysis`；跨模块 / 架构 / 不可逆任务过 `plan-control`。
3. **§4 工序扩为 0-7 步**：新增「1 分诊+拆解」「3 需求分析」「4 方案设计」，拆解未产出禁止进入编码。
4. **§4.1 三轨道**：Fast（纯问答/明确步骤/单文件低风险可逆，跳过方案与需求文档）/ Guided（多文件/部分假设，出 Mini Plan）/ Controlled（架构/数据模型/不可逆/高风险/需求含糊，走完整 plan-control §9）。轨道由风险 + 置信度 + 复杂度决定并带依据，分诊失准须重新分诊并说明。

**接线边界（关键）**：
- 技能正文留在 `.agents/skills/plan-control/SKILL.md` 与 `.harness/skills/main-dev/request-analysis/SKILL.md`。
- 十阶段流水线、L0-L3 路径分级、小改动判据已在 `.harness/rules/开发流程规范.md` §一，ADR 只引用不复制。
- 依据 AGENTS.md §2「规则全量常驻 / 技能按需加载」与 plan-control §18「禁制造与 AGENTS.md 平行的新规则体系」。

**编号消歧（附带修复）**：在 `docs/PLAN-harness-research-2026-10.md` 与 `docs/TODO-PRIORITY.md` 就地加 `P0-3` 撞车警示；**不做全库重编号**（会毁掉历史引用）。

## Consequences

- 每个任务开工前必须先出分诊结论；分诊结果决定是否产出拆解、需求文档、完整方案。
- 交接类结论一律需实测复核，未复核项必须显式标注，不能再静默当事实传递。
- AGENTS.md 由 228 → 250 行，仍在维护规则区间（200-350）。
- 与十阶段流水线为「入口 ↔ 细则」关系，无冲突；§5 Modification Level 仍为分级入口。
- 编号裸用被禁止，跨文档引用须带文档前缀（如 `hrs-P0-3`）。
- 纯文档变更，回滚为单 commit revert（需同步回退 `工程结构.md` 与 AGENTS.md §12 的 ADR 声明）。

## Rejected

- **把 plan-control / request-analysis 正文抄进 AGENTS.md**：违反 token 分工红线，且造成规则与技能双份维护。
- **新造一套平行流程规则体系**：plan-control §18 明禁；已有十阶段流水线可覆盖，只需接线。
- **全库重编号 P0-3**：会破坏 20+ 处历史引用；就地消歧成本更低且无破坏。
- **只写进技能而不上收 AGENTS.md**：用户明确要求写入最高规范；且技能是按需加载，不保证每次开工都读到。
