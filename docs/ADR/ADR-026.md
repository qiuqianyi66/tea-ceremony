# ADR-026：AI 回答质量评分（`ai_eval_traces.quality_layer`）

- **Status**: Accepted
- **Related**: ADR-016（评测 Trace）、ADR-023（兜底）、ADR-025（指标导出）

## Context

三大黄金指标（成功率 / 错误率 / P99）在 ADR-023 落地后已经能出数，但它们**只度量"通不通、快不快"，不度量"对不对"**。

这不是理论缺口，是实际踩到过的问题：多级兜底命中时会返回规则答案（`degraded=true`），成功率仍然是 100%、P99 反而更好——**指标全线变绿，回答质量却在下降**。同类问题还有：

- 向量检索降级退回关键词检索：不报错，召回质量下降；
- Tool Calling 路径改动：成功率不变，答案可能变差；
- 换 prompt / 换模型：从指标上完全看不出来。

没有质量维度，任何"优化"都只能靠肉眼看几条输出，无法量化也无法回滚判据化。

## Decision

1. **新增 `ai_eval_traces.quality_layer` JSONB 列**（V10），而不是新建评分表。
   理由：质量分是 trace 的派生属性、1:1、同生命周期。建表会引入额外关联与一致性维护（trace 归档时产生孤儿行），而 JSONB 让维度增减不再需要迁移。
2. **列可空，NULL = 未评分**。抽样是异步的，绝大多数行在评分前就是 NULL。**不能用 0 表示未评分**——0 会被看板读成"答得很差"。
3. **四维度各 1–5 分**：`relevance`（切题）/ `groundedness`（有据，不编造茶名与参数）/ `actionability`（给得出水温、时间、用量）/ `tone`（茶室语气而非客服腔）。另存 `overall`、`judge_version`、`judged_at`。
4. **双评分器 + 强制降级**：
   - `llm-v1`：LLM-as-a-Judge，走与对话相同的 key / 网关；
   - `rule-v1`：纯函数规则评分（关键词重合、茶名是否在 `teas` 表、温度是否落在该茶类区间、客服腔黑名单）。
   LLM 不可用（key 缺失 / 502 / 超时 / 熔断 / 输出非 JSON）时**一条都不许抛**，整批切到规则评分。判官挂了不能影响被测系统。
5. **判官独立熔断 lane**（`lane="judge"`）：判官失败不能连带熔断用户对话链路。
6. **默认关闭**（`tea.ai.quality.enabled=false`）。LLM 评分有成本，默认不烧钱；需要时用 `llm-enabled=false` 走零成本规则模式。
7. **抽样用部分索引** `idx_eval_traces_unjudged`：只覆盖 `quality_layer IS NULL AND error_code IS NULL`，不随已评分历史增长。

## Consequences

- 新增端点 `GET /api/v1/ai/metrics/quality`（需 JWT）。口径与 `GoldenMetricsReport` 一致：零样本返回 `null` 而非 0；已评样本 < 20 时不给中位数（小样本分位数不可信）。
- `AiEvalTrace` 实体加一个 `String qualityLayer`（JSONB 字符串映射）。因为 `ddl-auto=validate`，实体与迁移必须同时存在。
- **规则版有三个已知盲区**，写进 `RuleBasedJudge` 类注释：无「茶」后缀的编造名（如"仙雾龙井"）识别不到；语气判不出"礼貌但冰冷"；可操作性只数要素是否出现，不判参数对错（对错由有据性的温度区间承担）。**因此规则版不能作为质量结论的唯一依据**，它只是 LLM 不可用时的兜底与对照。
- 评分是双写窗口：同一 trace 先 NULL 后写入。评分幂等由 `UPDATE ... WHERE quality_layer IS NULL` 守卫，返回 0 行即为已被评分。

## Rejected

- **新表 `ai_quality_scores`**：见 Decision 第 1 条。
- **同步评分（在 chat 请求里判）**：会给用户请求加一次 LLM 往返，延迟代价不可接受，且判官故障会直接影响对话。
- **只做 LLM 判官不做规则版**：判官不可用时质量维度会整体消失，指标出现空洞；规则版保证任何时候都有一份可比对的下限数据。
- **把质量分并入三大黄金指标端点**：两者数据源与刷新节奏不同（黄金指标实时、质量分批量），混在一起会让接口语义模糊。独立端点更清晰。

## 反转条件

- 需要按 prompt 版本 / 模型版本做质量对比 → `judge_version` 已预留，但需要 trace 侧记录 prompt 与模型版本，届时加字段；
- 规则版与 LLM 版长期分歧 > 1 分 → 说明规则版不可信，应退化为"仅取样用"或直接移除；
- 标注集建立后 → 应该用标注集校准判官，而不是继续信 LLM 的绝对分。
