# ADR-009：文档治理与 AI 协作规范重构（V4）

- **Status**: Accepted
- **Date**: 2026-10-01

## Context

AGENTS.md 551 行，超过自定维护上限（200-300 行最舒服、超 500 行「就是在跟自己打架」），文档重量逐渐超过项目复杂度；规范分散在 AGENTS.md / CONTEXT.md / V3_ROADMAP.md / CHANGELOG.md；AI 协作上下文需要重新整理；type-check / test / lint / verify 等验证入口分散，未形成统一门禁；三处失修（摘要阶段六表述、ADR 编号过时、行数超限）需要一次结构性收敛。

## Decision

1. **AGENTS.md 重构为 V4**：551 → 目标 250-350 行，保持 13 节结构，每节 ≤ 20-30 行；定位为「AI 行为控制面」，不是项目百科；技术说明、部署全文、历史记录外移到 docs / CHANGELOG；新增 **AI Change Protocol**（理解上下文 → 确认影响范围 → 修改 → 运行验证 → 报告证据，禁止直接改代码 / 加依赖 / 改架构）与 **Modification Level**（L0 文档 / L1 UI：type-check+build / L2 业务逻辑：test / L3 架构：ADR + migration test）。
2. **docs 分层**：ADR 从 CONTEXT.md 拆为 `docs/ADR/ADR-0XX.md` 独立文件（统一 Status / Context / Decision / Consequences / Rejected 格式，ADR-001~008 原样迁移，Rejected 原文未载明处如实标注）；CONTEXT.md 只保留术语表、ADR 索引、架构关键词与待办；技术说明进入 `docs/architecture/system-overview.md`。
3. **commit 规范改为英文 conventional commits**（`type(scope): desc`，如 `feat(brew): add tea pouring animation`），与历史中文 commit 风格断裂，自本 ADR 生效；学习记录同步更新。
4. **新增 `npm run quality` 统一门禁**：`lint && type-check && test && build && verify`，提交前前端默认入口；AGENTS.md 验证基线同步改写。
5. **ADR 约定变更**：AGENTS.md 原有「禁止另建 docs/adr/、ADR 统一写在 CONTEXT.md」作废，改为「ADR 一律写入 docs/ADR/ 独立文件」。

## Consequences

- AGENTS.md 成为纯行为控制面，降低 AI 上下文污染与维护成本。
- ADR 独立文件支持单条演进与状态管理（Proposed / Accepted / Superseded），便于追踪。
- 历史 commit 保持中文，新 commit 用英文 conventional；跨工具（AI / CI / 语义化发布）解析更可靠。
- quality 命令成为提交前唯一前端门禁入口，降低漏跑验证的概率。
- 需同步迁移：CONTEXT.md 原 ADR 段（已完成）、AGENTS.md 技术栈 / 部署 / 更新记录段（本次重构完成）、复盘记录进 CHANGELOG。

## Rejected

- **ADR 继续留在 CONTEXT.md**：单文件随数量增长难以阅读与做状态管理，且与 docs 分层目标冲突；编号顺承会持续过时（本次已发现「下一个 ADR-006」实际已到 ADR-008 的失修）。
- **保留中文 commit 格式**：与主流开源协作格式脱节，不利于外部工具（commitlint、release-please、AI 解析）使用。
- **不设统一 quality 门禁**：验证入口分散已被验证为提交前漏跑的直接原因。
