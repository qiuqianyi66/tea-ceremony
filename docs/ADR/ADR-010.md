# ADR-010：后端重写 ORM 选型（Spring Data JPA）

- **Status**: Accepted
- **Date**: 2026-10-04

## Context

后端从 FastAPI + SQLAlchemy 2.0（async）重写为 Spring Boot 3.5 + Spring AI Alibaba。数据访问层需选型：Spring Data JPA（Hibernate）或 MyBatis-Plus。两者在 Java 生态均为主流：JPA 是 Jakarta EE 标准实现、与现有 SQLAlchemy 的"实体映射"心智同构；MyBatis-Plus 是国产增强、SQL 可控性强（tulingshop 参考项目用后者）。选型影响 Entity/Repository 写法、事务边界、迁移配套、团队（单人）学习成本与长期可维护性。

## Decision

**采用 Spring Data JPA（Hibernate 6.x）**，理由：

1. **心智同构**：现有 SQLAlchemy 是"对象关系映射 + 会话管理"模型，JPA 的 EntityManager / Repository / @Transactional 与其语义一一对应，迁移旧代码时概念映射成本最低。
2. **标准生态**：Spring Boot 官方一等公民，@DataJpaTest、Specification、@EntityGraph、审计（@MappedSuperclass + AuditingEntityListener）开箱即用；MyBatis-Plus 是第三方增强，依赖私有注解体系。
3. **与编码规范一致**：`.harness/rules/编码规范.md` 已定义四层对象分离（DTO/Entity/VO/Model）、软删除（@SQLDelete + @SQLRestriction）、乐观锁（@Version）、审计字段——均为 JPA 原生能力；MyBatis-Plus 的 @TableLogic 虽也能软删，但非标准、迁移到标准 Hibernate 语义更干净。
4. **事务语义**：@Transactional(rollbackFor) + REQUIRES_NEW 是 JPA 标准行为；MyBatis-Plus 依赖 Spring 事务管理器同源但 SQL 拼装差异大。
5. **AI 编码辅助**：SAA / Spring AI 官方示例与文档全部基于 JPA 或 JDBC 模板，与重写主线（Spring AI Alibaba）生态一致。

复杂度上限（N+1 / 大查询 / 批量）通过 Specification + @EntityGraph + 分页（PageRequest）显式管控，已写入编码规范 §5（禁 N+1、大列表必分页）。

## Consequences

- Entity 用 JPA 注解（@Entity / @Table / @Id / @GeneratedValue），软删统一 @SQLDelete + @SQLRestriction；Repository 继承 JpaRepository。
- 复杂查询用 Specification / @Query（命名参数防注入），禁止字符串拼接（红线 #6 数据访问）。
- 迁移配套：Flyway（ADR-011），禁用生产 ddl-auto: update（红线 #7）。
- 代码评审按编码规范 §5 逐条核对 N+1 / 分页 / 软删 / 索引。
- 测试配套：@DataJpaTest（切片）+ Testcontainers PostgreSQL 集成测试。

## Rejected

- **MyBatis-Plus**：与现有 SQLAlchemy 心智不同构（XML/SQL 优先），且引入第三方私有注解体系、与 SAA 官方示例生态不一致；tulingshop 用它不代表 tea 必须复用（tea 是重写而非移植）。
