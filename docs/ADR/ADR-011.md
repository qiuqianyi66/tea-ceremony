# ADR-011：后端重写工程决策（构建 / 迁移 / 缓存 / 数据 / 成本 / 角色）

- **Status**: Accepted
- **Date**: 2026-10-04

## Context

PRD v0.2 第 14 节待确认项在用户评审后全部定案（2026-10-04）。本节将六项工程决策统一落档，作为 M1 后端骨架搭建的依据；其中 ORM 已在 ADR-010 单独记录，不再重复。

## Decision

1. **构建工具：Maven**（默认）——SAA 官方示例全为 Maven，pom.xml 标准化、GitHub Actions 缓存成熟；单体应用无需 Gradle 的增量构建收益。
2. **数据库迁移：Flyway**（默认）——纯 SQL 脚本（V1__xxx.sql）与 `.harness/changes/{feat}/db-migrations.sql + rollback.sql` 成对模式天然契合；Spring Boot 零配置集成（spring.flyway.*）；过渡期旧后端仍用 Alembic 直至迁移完成。
3. **Redis：不引入**【已被 ADR-012 修订：2026-10-05 起引入 Redis，见 ADR-012】——tea 为单实例应用，JWT 无状态会话无需 Redis；限流用单机内存滑动窗口；缓存用 Caffeine 本地缓存（容量+过期+统计），文化数据低频读足够；biz-dev-skill 03-redis-cache 裁剪不建。未来若需分布式能力再评估。
4. **文化数据 seeds：先迁移现有真实数据**——从 `backend/seeds/` 与 `src/data/` 整理迁移进新库，零编造、可核对（编码规范文化纪律：不确定标"待核实"，优先用已有数据）；扩充（200 茶 / 100 人 / 500 诗）作为后续增强，带来源标注。
5. **AI 成本：设每日预算告警**——新增 `ai_usage_logs` 表（用量审计）+ 每日统计定时任务（ShedLock 防重）+ 超阈值告警（日志/通道见开发流程规范 §36）；"不计成本"不意味着放任失控，token 计量与告警是生产级收敛的必要项。
6. **专家角色命名：技术命名先行，中文文案后置**——PRD 定 5 角色概念（荐茶 / 品鉴 / 文化 / 冲泡 / 成长），代码用 `RecommendAgent / TastingAgent / CultureAgent / BrewCoach / GrowthMentor`；中文名（荐茶师/品鉴师/茶文化学者/冲泡教练/成长导师）待产品文案阶段统一，不阻塞 M1。

## Consequences

- M1 后端骨架按 Maven + Flyway + Caffeine（无 Redis）搭建；docker-compose 不含 redis 服务。
- `.harness/skills/biz-dev/03-redis-cache` 不建（按需裁剪），替换为 Caffeine 缓存技能（如纳入 01-crud 或独立条目，见技能清单）。
- Flyway 迁移脚本成对（up/down）为硬性提交条件（编码规范红线 #7）。
- ai_usage_logs 表纳入数据模型与 wiki 同步；成本告警定时任务在 M5 AI 主线实现。
- 角色技术命名写入代码注释与 glossary，产品文案定稿后再统一展示层措辞。

## Rejected

- **Gradle**：学习成本与构建速度收益对单体应用不成比例。
- **Liquibase**：XML/YAML changelog 抽象层对 SQL-first 团队是额外心智负担。
- **引入 Redis**：单实例场景引入分布式组件属于过度设计（同 ADR-010 拒绝 MyBatis-Plus 的过度设计逻辑）。
- **seeds 直接扩充**：无来源扩充文化数据违反"不编造茶文化"红线。
- **不设 AI 成本告警**：AI 用量不可见 = 生产事故未被观测（与观测期 30 分钟无异常门禁冲突）。
- **中文角色名先行**：产品文案未定，先定展示层措辞会阻塞技术主线。
