# ADR-014：ArchUnit 事务与响应契约机械化（H18/K10）

- **Status**: Accepted
- **Date**: 2026-10-08
- **Supersedes**: 无（扩展现有 LayerDependencyTest 的 ArchUnit 规则范围，红线 #1 之外新增事务/响应契约检查）

## Context

编码规范 §7 明文三条事务与响应规范，此前仅靠人工评审执行：

1. 写方法 `@Transactional(rollbackFor = Exception.class)`（checked exception 也回滚）。
2. 只读方法 `@Transactional(readOnly = true)`。
3. 错误统一 `ApiResponse<T>` + `{code, message}`（Controller 返回类型）。

基线扫描（2026-10-08，全量 `backend/src/main`）：

- **写方法缺 rollbackFor：6 处**——ChatMemoryService L33/L45/L96、AuthService L32、TastingRecordService L36/L97。均只注解 `@Transactional`，checked exception 不触发回滚。
- 只读 readOnly=true：全部合规（TeaService/PromptService/ChatMemoryService 等 9 处）。
- Controller 返回类型：6 个 controller 全部方法返回 `ApiResponse<...>`，0 违规。

Harness 285「约束必须自动化」原则：人工评审依赖评审者记忆，机械化为 ArchUnit 断言后由 `mvn test`（CI Maven 门禁）强制。

## Decision

在 `LayerDependencyTest.java` 追加两条 ArchRule（错误信息三要素：❌ 问题 / ✅ FIX / 📖 See）：

1. **`transactionalWriteMethodsNeedRollbackFor`**：`..service..` 包内方法，标注 `@Transactional` 且非 `readOnly=true` → 必须显式含 `rollbackFor`（值为 `Exception.class` 或其父类 `Throwable.class`）。
2. **`controllersReturnApiResponse`**：`..controller..` 包内 public 方法 → 返回类型必须为 `ApiResponse<?>`（含泛型）。

同步修复 6 处基线违规（加 `rollbackFor = Exception.class`，行为变化符合规范意图：checked exception 参与回滚）。

## Consequences

- `mvn -q test`（CI `backend-springboot` job）成为事务/响应契约的机械门禁；新增写方法不带 rollbackFor、controller 返回裸类型 → 测试红。
- 修复 6 处基线违规独立 commit，可与规则 commit 分开回退。
- 只读方法保持 readOnly=true 显式声明，不加 rollbackFor（规范区分）。

## Rejected

- **仅对新代码生效**：ArchUnit 全量类扫描无法区分新旧代码，规则必须全量成立，否则留洞。
- **放宽规则只查部分包**：按包豁免会让新代码绕过，丧失门禁意义。
- **不做此机械化**：人工评审已漏 6 处，证明不自动化必复发。
