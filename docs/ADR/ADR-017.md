# ADR-017：运行时领域技能（agent_skills，第一版）

- **Status**: Accepted
- **Date**: 2026-10-09
- **Supersedes**: 无（新增决策）

## Context

AI 项目化改造能力补齐（REQ-ai-project F-B1）：茶文化问题需要领域子指令（茶器/茶诗/产区/茶人各有专业口径），而专家 prompt 是通用的。把领域知识硬编码进 SYSTEM_PROMPT 会让 prompt 膨胀、不可运营。

三个设计问题：

1. **注入粒度**：按领域命中注入子指令，未命中不膨胀上下文。
2. **可运营性**：子指令存表可增改（灰度/回滚同 agent_prompts 模式），不随代码发版。
3. **命中判定**：领域关键词要顺序稳定（同词多领域不随机）。

## Decision

**运行时领域技能表 `agent_skills` + 路由器**：

1. **表**（Flyway V6）：`agent + domain + skill + status`，`uk(agent, domain)` 唯一，种子 4 条（librarian 的 teaware/poem/region/person 子指令，引导性规则不编造事实）。
2. **`AgentSkillRouter`**（@Component）：`detect(question)` 按固定顺序关键词命中领域（LinkedHashMap）；`load(agent, domain)` 取 active 技能（无 → 空串）。
3. **注入点**：`LibrarianAgent.chat()` RAG 检索后、LLM 调用前，命中领域则拼 `【领域技能·domain】` 进 system prompt；未命中不加（上下文不膨胀）。
4. **模式复用**：同 `agent_prompts` 的 status/版本化惯例；prompt 版本化承重墙（无 active → 内置常量回退）不变。

## Consequences

- 新表 Flyway V6，up/down 成对（`.harness/changes/agent-runtime-skill/`）。
- `LibrarianAgent` 构造器 +1 依赖（spring 注入）。
- 技能内容可运营：INSERT/UPDATE agent_skills 即生效（重启加载），无需发版。
- 与评测体系衔接：T11 评测集 adversarial 用例可断言领域命中（RAG 前注入）。

## Rejected

- **硬编码进 SYSTEM_PROMPT**：不可运营、prompt 膨胀 → 否。
- **文件配置加载技能**：丢失版本化/灰度能力（agent_prompts 已证明表模式）→ 否。
- **skill 合并进 agent_prompts 表**：两表语义不同（prompt=完整系统提示，skill=领域子指令），混合后回退粒度模糊 → 独立表。
