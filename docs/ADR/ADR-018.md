# ADR-018：Spring AI Alibaba Graph 引入暂缓

- **Status**: Accepted
- **Date**: 2026-10-09
- **Supersedes**: 无（新增决策）

## Context

精读语雀《Spring AI Alibaba Graph〈HR 招聘全流程 workflow-agent 实战〉》+ gitee
`xscodeit/spring-ai-alibaba-xs`（hr-recruitment-agent + course-1~6）后，需判断是否引入 Graph 编排。

三项前置事实：

1. **教材可信度低**：跑图实测推翻其三条核心说法（`experience_scorer`/`culture_scorer` 无入边永不执行、
   不配 Executor 照样并行、`PASS_THRESHOLD=0` 与文档矛盾）；项目零测试、含真 bug、关键章节锁付费墙。
   详见 `docs/research-spring-ai-alibaba-graph-2026-10.md` §10。
2. **依赖已就位**：`spring-ai-alibaba-agent-framework:1.1.2.4-security-fix` 传递依赖
   `spring-ai-alibaba-graph-core` 同版本（已核对 pom + 用 tea classpath 实跑通过），
   **引入 Graph 零新增依赖**——所以这不是成本问题，是需求问题。
3. **tea 现状**：五专家（LIBRARIAN/ADVISOR/TASTER/BREWER/MENTOR）单请求单专家路由 + RAG +
   会话记忆 + Trace（ADR-016）+ 运行时技能（ADR-017）；评测体系已建（50 条 / 98 考点）。

## Decision

**暂缓引入 Graph 编排**（StateGraph / 子图 / HITL / Checkpoint / 时间旅行）。

理由：

1. **四维甄别 0/4**：无内生需求（是外部课程输入）、无用户要求、无竞品压力、团队自用不成立。
   按 `REQ-quality-backlog` §1.3「四维甄别未过不扩功能面」。
2. **业务闭环无对应环节**：入席→选茶→备器→煮水→冲泡→品鉴→成长中，
   没有「一次请求内多步有状态 AI 编排」的需求。冲泡流程是**前端状态机** + 参数计算，不是 LLM 编排。
3. **HITL 与既有决策硬冲突**：AGENTS.md §13 明令「冲泡页零点击闭环，禁止为温杯/醒茶/出汤加回手动确认按钮」。
   Graph 的核心卖点 HITL（人工介入）在 tea 冲泡场景是**回退**，不是增强。
4. **第二套状态模型的成本**：引入 = OverAllState 与现有 AiChatVo/DTO 并存，
   增加认知负担，且需自建「节点可达性」测试体系（教材项目正是栽在这）。

**但采纳一个不依赖 Graph 的低成本件**：AI 会话配额（F-6，`tea.ai.max-calls-per-session`）。

> **补充说明（2026-10-09 review 后）**：F-6 按 sessionId 计数，但前端 `teaAI.ts` 走裸 fetch
> 匿名调用（不带 Authorization、不带 sessionId），命中 `sessionId == null` 分支直接放行，
> **当前无生效对象**。前端已由 `RateLimitFilter` 按 IP 限流（10/min）覆盖。
> F-6 定位修正为「为登录 + sessionId 的调用方预留」，非「已上线」。代码保留、注释与本文如实标注。

**另两项曾候选、经实证后砍掉**：
- 结构化输出（F-7）：Q1 确认 tea 无「文本解析 LLM 输出」代码，无落点 → 砍。
- 工具缓存（F-8）：Q3 实证缓存命中率 0-1%（query 层与关键词层皆然），不利 → 砍，不引入 Caffeine。

## Consequences

- ai 域不新增 graph 包；`pom.xml` 不新增依赖。
- 会话配额（F-6）独立 commit，可单独回滚；**当前无生效对象（前端匿名调用不计数），为登录调用方预留**。
- 评测判分真实性修复（F-1/F-2）已落地：报告新增 `programOnly` / `judgeCoverage` 字段，
  ITERATIONS.md 加口径标注——**v1/v2 的 0.82/0.96 是 judge off 的 program-only 口径，不得直接写进简历**。
- 后续会话读本 ADR 即可，不重复论证。

**触发重评条件**（满足任一重新评估）：

1. 出现**真实的多步有状态 AI 流程**需求（如「一次请求内 AI 自主完成选茶→算参→评分→给建议」）。
2. 前端**明确要求**断点续传/人工审批（当前 §13 禁止，故不成立）。
3. 需要**时间旅行回放**作为产品功能（非仅调试用途）。

## Rejected

- **全量引入 Graph**：四维 0/4，无需求牵引 → 否。
- **`LlmRoutingAgent` 替换 `AgentOrchestrator`**：语义上是「选一个执行」非接力，
  但属架构级替换，现状关键词路由无痛点 → 否。
- **多 agent 接力流水线**：H9 已判砍（`REQ-ai-project` §4），延续不做。
- **照抄课程项目结构**：教材零测试 + 含真 bug，照抄会带入缺陷 → 否。
