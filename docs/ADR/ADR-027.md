# ADR-027：品鉴综合评分按六大茶类加权

- **Status**: Accepted（v1 启发式权重，待 live 数据校准）
- **Related**: AGENTS §3 评分模型契约（八维口感评分 × 冲泡工艺系数）

## Context

`calculateOverallScore` 现状为八维等权平均（苦涩度反向为适口度）× 工艺系数。等权的隐含假设是「八维对所有茶同样重要」，这与茶道常识不符：

- 青茶（乌龙）以香气与回甘为王，body 单薄并不致命；
- 黑茶（普洱）醇厚陈香是骨架，甜感淡不扣分；
- 红茶要求顺滑甜醇，苦涩权重应高于绿茶（绿茶微苦涩属正常）；
- 绿茶重鲜爽高扬，shape/外形权重天然低于内质。

此前评估一直停留在提案状态。本次落地为 v1：权重走茶类查表，不侵入工艺系数与 UI。

## Decision

1. **`calculateOverallScore(dimensions, processFactor, weights?)`** 新增可选第三参；缺省 = 等权，旧调用与旧记录行为完全不变（向后兼容）。
2. **权重在服务层归一化**（加权平均 ÷ 权重和），权重值只表达相对重要性，和不必为 8。
3. **`TEA_CATEGORY_WEIGHTS` 查表**（`src/services/scoring.ts`）：六大茶类（绿茶/白茶/黄茶/青茶/红茶/黑茶）各一组八维权重；调用方 `stores/tea.ts` 按 `currentTea.type` 查表，无匹配茶类回落等权。
4. **v1 权重为启发式初值**，不宣称校准：苦味维度绿茶 0.7 / 红茶 1.2，青茶香气 1.6、回甘 1.4，黑茶 body 1.5。待 DashScope 充值、live 品鉴数据积累后再按真实分布校准（见交接 TODO）。
5. **不改工艺系数**、不改八维采集界面、不迁移历史记录（历史记录分数是当时算法的快照，不重算）。

## Consequences

- 新记录的综合分会随茶类变化：同一套八维手感，青茶高香会比等权更高分。
- 风险：v1 权重未经数据验证，可能与用户直觉冲突 → 因此权重集中一张表、单行可改，不改算法结构。
- 后续校准路径：积累 ≥200 条带茶类记录后，按「维度分数与用户主观复购/收藏的相关性」回归出权重，替换本表即可。
