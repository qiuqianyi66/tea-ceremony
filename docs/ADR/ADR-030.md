# ADR-030：Spring Boot 4 迁移评估（结论：暂缓，被 spring-ai-alibaba 阻塞）

- **Status**: Deferred（2026-11-08 实测评估，未合入；Dependabot #199 `spring-boot-starter-parent 3.5.3→4.1.2` 不可单独合并）
- **Related**: 分支 `chore/spring-boot-4.1.2`（仅本 ADR，代码改动已回退）；Dependabot #199 / #201 / #202；`backend/pom.xml`；ADR-029（onnxruntime 1.20.0 锁定）

## Context

Dependabot 提出 `spring-boot-starter-parent 3.5.3 → 4.1.2`（#199）。原假设是"Boot 版本升级可单独一轮：ADR + 全量回归"。2026-11-08 在本机（JDK 21.0.10 / Maven 3.9.12 / Docker 29.8.2）实跑验证该假设，结论：**不成立**，升级被 AI 承重墙阻塞。

实测命令与结果（`.tmp/sb4-1108/` 日志，均已跑过）：

| 步 | 命令 | 结果 |
|---|---|---|
| 基线 | `mvn -DskipTests compile`（Boot 3.5.3） | BUILD SUCCESS |
| 编译 | 改 parent 4.1.2 后 `mvn -DskipTests compile` | BUILD SUCCESS（180 源文件，仅 1 处 deprecation 提示） |
| 测试 | `mvn test` | **562 测试 / 89 error / 19 个测试类红** |

## Decision

**暂不迁移 Boot 4。** 保持 3.5.3，撤回分支上的全部代码改动，只保留本 ADR 作为下次尝试的起点。

阻塞点是唯一的、不可绕过的一处：**spring-ai-alibaba 1.1.2.4-security-fix 与 Spring Framework 7 二进制不兼容**。

```
java.lang.NoSuchMethodError: 'void org.springframework.http.HttpHeaders.addAll(org.springframework.util.MultiValueMap)'
  at org.springframework.web.client.DefaultRestClientBuilder.defaultHeaders(DefaultRestClientBuilder.java:245)
  at com.alibaba.cloud.ai.dashscope.api.DashScopeApi$Builder.build(DashScopeApi.java:830)
```

`javap` 实测签名差异（本地 `~/.m2` 全版本比对）：

- spring-web 6.2.x（含 6.2.8 / 6.2.12 / 6.2.14 / 6.2.18）：`addAll(MultiValueMap<String,String>)` 存在
- spring-web 7.0.x（7.0.2 / 7.0.10）：**只剩** `addAll(String, List)` 与 `addAll(HttpHeaders)`，`MultiValueMap` 重载被删除

DashScope 自动装配在 `DashScopeChatModel` 建 bean 时即崩，AI 链路是承重墙（ADR-003 降级策略的前提），不能排除。

**兼容版本的唯一出口是里程碑版**：`com.alibaba.cloud.ai:spring-ai-alibaba-starter-dashscope` 的 maven-metadata 里，1.x 线止于 `1.1.2.4-security-fix`（当前版本），Boot 4 兼容线只有 `2.0.0-M1.1`，其 pom 显式依赖 `spring-boot-starter 4.0.0`。

因此 **#199 与 #201/#202（spring-ai 2.0.x）是同一次升级，不能拆**（原先"Dependabot PR 各自独立合并"的前提在 AI 栈上失效）。

## Consequences

- Boot 4 迁移必须与 spring-ai-alibaba 2.0 GA（或至少 2.0.0-M 系列已被项目验证）同步排期；单升 Boot 不可行，别再试第二次。
- 下次尝试可直接复用本轮量出的 5 类破坏面（均已定位到具体修法，未提交，仅记录）：

| # | 破坏面 | Boot 3 | Boot 4 | 修法 |
|---|---|---|---|---|
| 1 | `@MockBean` | 存在 | 删除 | 改 `@MockitoBean`（`org.springframework.test.context.bean.override.mockito`），7 个测试文件 9 处 |
| 2 | Web 测试切片模块 | `spring-boot-test-autoconfigure` | 拆为 `spring-boot-webmvc-test` | 加 `spring-boot-starter-webmvc-test`；`@WebMvcTest`/`@AutoConfigureMockMvc` 移到 `org.springframework.boot.webmvc.test.autoconfigure` |
| 3 | JPA 测试切片模块 | 同上 | 拆为 `spring-boot-data-jpa-test` / `spring-boot-jdbc-test` | 各加依赖；`DataJpaTest` → `org.springframework.boot.data.jpa.test.autoconfigure`，`@AutoConfigureTestDatabase` → `org.springframework.boot.jdbc.test.autoconfigure` |
| 4 | `TestRestTemplate` | `org.springframework.boot.test.web.client` | `org.springframework.boot.resttestclient` | 加 `spring-boot-resttestclient`，7 个集成测试改 import |
| 5 | Flyway 自动装配 + Jackson 2 | Boot 3：Flyway 在 `AutoConfigureDataJpa.imports` 内；Jackson 2 默认装配 | Boot 4：Flyway 独立成 `spring-boot-flyway`（`AutoConfigureDataJpa.imports` 只剩 JPA 两项，`.imports` 内容已比对确认）；Jackson 2 默认改 Jackson 3（`tools.jackson`） | 加 `spring-boot-starter-flyway`（迁移才会执行，否则 `missing table [ab_experiments]`）；加 `spring-boot-jackson2`（官方兼容模块，避免改 9 个类 + 实体 JSONB 的 `JsonNode` 类型） |

- 未实测项（标 unknown，不当结论用）：agent-framework / MCP server / openai starter 三条 AI 通道在 Framework 7 下是否同样出现 `NoSuchMethodError`；本轮只走到 DashScope 装配即中止，其余 `spring-ai 1.1.2` 系 jar 的运行时兼容性未逐一验证。
- 反转条件：`spring-ai-alibaba` 发布 2.0 GA（非 milestone）且 `spring-ai` 对应 GA 版本可用时，重启一轮迁移；届时直接把上表 5 项照做，再跑 `mvn test` 全量 + `npm run quality`。

## Rejected

- **只升 Boot、AI 走 gateway profile 绕过 DashScope 装配**：生产主路径就是 DashScope（ADR-003/ADR-023），排除装配等于线上无 AI；且 `spring-ai` 其余自动装配同属 1.x 编译产物，风险未消除。
- **升到 spring-ai-alibaba 2.0.0-M1.1（milestone）**：承重墙引入未发布版本，且需连带改 Spring AI 2.x 的 ChatClient/Advisor/Tool API，回归面覆盖 562 个测试 + 6 轮 AI 评测；不可逆风险高于收益。留待 2.0 GA。
- **回退 Boot 3.5.3 但保留测试代码现代化（@MockitoBean 等）**：这些改动只在新测试模块结构下成立，Boot 3 上不编译，不能单独保留。
