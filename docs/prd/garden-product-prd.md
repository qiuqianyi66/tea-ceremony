# 茶园（garden）产品需求文档（PRD V2 · 企业级）

> 对齐 `frontend-product-prd.md` / `m5-agent-product-prd.md` 企业级写法。设计模式**参考成熟养成类产品**（蚂蚁森林/多多果园：能量生产→收集→使用 + 任务/社交/反馈/奖励四模块 + 排行榜 + 勋章，Kano 模型文献），不造轮子。
> 事实来源（只读核实）：`V1__init.sql`（garden_plants 表）、`scripts/verify-gardens.cjs`（3D 茶园四园验证）、E2E 导航路径含 garden、`3D_SPEC.md`（茶空间约束）、M5 PRD（mentor 依赖成长数据）。日期：2026-10-07。版本：V2.0（R1/R2 迭代后定稿）。

## 1. 背景与定位

「一盏茶」的沉浸式养成层：品鉴/冲泡/学茶等**茶修行为**转化为"茶力能量"，能量浇灌**3D 茶园**植物成长（视觉已就绪），成熟后获得**称号/稀有茶器**等奖励。核心目标：把"来喝茶"变成"来养园"——用长期成长与情感依恋提升回访（蚂蚁森林模式：虚拟物成长 + 成就外化）。

当前状态：garden_plants 表已建（最小集）；3D 茶园视觉已验证（四园晴雨）；**养成玩法（能量/成长/奖励）需求未定**——本 PRD 补齐。

## 2. 用户角色与核心场景

| 角色 | 诉求 | 对应场景 |
|---|---|---|
| 茶小白 | 被鼓励持续学茶 | 每天完成 1 次冲泡 → 能量 → 植物"发新芽"（即时反馈） |
| 茶爱好者 | 有目标感 | 攒能量解锁稀有茶器/称号（里程碑） |
| 老茶客 | 成就感外化 | 茶园满级/稀有植物/周榜（社交对比） |
| 游客 | 低门槛体验 | 体验式种植（不落数据，不参与排行） |

核心场景：
1. **浇水即成长**：完成品鉴/冲泡 → 自动获得能量（无需额外操作）→ 能量自动浇灌 → 植物阶段可视化（芽→苗→树→开花）
2. **里程碑收获**：能量攒够阈值 → 解锁对应植物阶段/稀有茶器 → 获得称号
3. **每日回报**：连续每日浇水（streak）→ 额外能量/稀有种子
4. **榜单激励**：周榜（短期）+ 总榜（长期），好友能量可见（社交，S2 可选）

## 4. 功能域需求（Given-When-Then）

### F-G1 能量生产（行为→能量，自动转化）

- Given 用户完成一次品鉴记录（tasting_records 落库），Then 自动产生能量（默认规则：每 100 字笔记 +10 能量 / 每次冲泡 +5，配置化），无需用户额外操作（蚂蚁森林"行为自动转化"模式）。
- Given 用户连续 N 天有能量行为，Then 连续奖励（streak 第 3/7 天翻倍），中断后重置（可配置宽限 1 天）。
- Given 游客行为，Then 产生体验能量但**不落库**（体验模式，无排行/无持久）。

### F-G2 能量收集与浇灌

- Given 有未收集能量，Then 茶园页可见"待收能量"气泡，一键收集（当日未收次日 0 点结算入账）。
- Given 收集能量，Then 按当前植物进度消耗 → 植物阶段推进（芽→苗→树→开花→结果，阶段表可配置）。
- Given 植物满级，Then 能量转入"能量池"供解锁奖励（不浪费）。

### F-G3 植物成长与 3D 反馈

- Given 植物阶段推进，Then 3D 茶园对应植物视觉升级（复用现有四园视觉，接阶段状态映射；交互细节走 3D_SPEC 约束）。
- Given 植物满级收获，Then 生成收获记录 + 成就勋章（勋章池：首棵茶树/满级园/连续 7 天等）。

### F-G4 奖励与权益（里程碑解锁）

- Given 能量池达到阈值（如 500/2000/5000），Then 解锁对应奖励：稀有茶器（teawares.rarity 过滤）/ 称号（成长体系联动）/ 茶园装饰。
- Given 奖励已领，Then 幂等防重（user_id+reward_id 唯一）。

### F-G5 排行榜（社交激励，S2 可选）

- Given 周榜开启，Then 按周能量增量排名（短期激励，本周公平起点）。
- Given 总榜开启，Then 按累计能量排名（长期行为反馈）。
- Given 好友系统就绪（S2 依赖账号/好友），Then 好友能量可见/互访；S1 仅全局榜。

### F-G6 数据与治理

- Given 任意能量写入，Then 落 `garden_energy_events`（事件账本：user_id/amount/source/created_at，append-only，防通胀可审计——成长体系同模式）。
- Given 阶段/奖励/勋章配置变更，Then 走配置表（DB 或 JSONB），灰度可回滚（不做硬编码常量）。
- Given 离线操作，Then 能量事件带 client_id 幂等（沿用 tasting_records 幂等模式）。

## 5. 非功能需求矩阵

| 维度 | 要求 | 验收判据 |
|---|---|---|
| 一致性 | 能量事件账本 append-only；奖励幂等；游客不落库 | 重复提交不重复计能量 |
| 性能 | 茶园页加载 P99 < 500ms（3D 资源缓存，PWA 离线可看） | 性能基准记录 |
| 可维护 | 阶段/奖励/勋章配置化（非硬编码）；事件账本可审计 | 改一个奖励阈值不动代码 |
| 可扩展 | 新行为源 = 新增事件触发（配置）；新奖励 = 池中注册 | 30 分钟内加一种能量来源 |
| 防通胀 | 能量产出速率建模（周产 vs 周消耗平衡，超标告警） | 产出/消耗报表可用 |
| 安全 | 能量/奖励接口走鉴权（登录用户专属）；游客模式隔离 | 未登录不可领奖 |

## 6. 架构决策（ADR 候选）

| 决策 | 结论 | 理由 |
|---|---|---|
| G1 事件账本 | `garden_energy_events` append-only + 聚合视图 | 与成长 XP 同模式，可审计防通胀（行业标准：XP 事件账本） |
| G2 配置化 | 阶段/奖励/勋章存配置表/JSONB，不硬编码 | 灰度回滚 + 运营可调 |
| G3 幂等 | user_id+client_id（沿用 tasting_records） | 离线重放防重 |
| G4 排行 | S1 全局榜 → S2 好友榜（依赖账号体系） | 最小切片先行 |

## 7. 数据模型（新表 DDL 草案，Flyway 实施时版本号顺延）

```sql
-- garden_energy_events（能量事件账本，append-only）
CREATE TABLE garden_energy_events (
    id         INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id    INTEGER NOT NULL,
    client_id  VARCHAR(64) NOT NULL,
    amount     INTEGER NOT NULL,
    source     VARCHAR(30) NOT NULL,      -- tasting/brew/streak/quest
    created_at TIMESTAMP NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_garden_energy_events_user_client ON garden_energy_events (user_id, client_id);
-- garden_plants 扩展列（V4 追加，回填默认值）
-- status 语义：planted/growing/blooming/harvested；plant_type 复用现有字段
```

- 沿用 garden_plants 幂等键；阶段推进 = 事件聚合 + 状态迁移（事件驱动，不直接改列值）。
