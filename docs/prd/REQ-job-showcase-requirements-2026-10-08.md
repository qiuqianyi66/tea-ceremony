# 求职亮点物（一盏茶作品集展示物）— 需求分析（PRD 级）

> 阶段 1 output（`.harness/rules/开发流程规范.md` §一）。本需求经用户确认后才进阶段 2 方案设计。
> 背景：用户读《零 AI 产品经验拿 offer》方法论长文（X 链接），要求基于当前正在开发的「一盏茶」项目产出一个让面试官「眼前一亮」的求职亮点物。目标岗位：软件交付经理 · 云计算方向（2027 届）。
> 全部量化数字已于 2026-10-08 从仓库实测（证据见下），无来源数字一律标「待核实」，禁止编造。

## 一、范围边界

### 做什么

1. 产出「一盏茶」项目求职展示物：**单文件交互式 HTML 作品集页**，面试官/HR 打开即懂、可交互、可部署。
2. 内容五块：项目一页式总览、技术架构、量化仪表盘、STAR 项目讲述、工程治理亮点 + 目标岗 JD 对照（三方向为主 + 软件交付经理附版）。
3. 量化数字全部来自仓库实测；挖不到的标「待核实」。
4. 附带一份 STAR 项目经历文档（Markdown，可直接粘贴进简历/求职信）。
5. 项目口径：**亮点讲满 + 状态如实**——已完成模块讲满讲透，开发中/部署完善中状态如实标注（与 2026-10-08 简历母版弱化口径一致，不吹"已上线完整产品"）。

### 不做什么（明确排除）

1. 不改 tea 产品任何代码与文档治理体系——展示物是纯新增文件。
2. 不编造性能数字（如查询耗时、QPS、并发量，tea 仓库无此指标则不写）。
3. 不做整份简历/求职信——只做「项目展示物 + 项目经历」。
4. 不做投递管理表/面试题库/AI 模拟面试——那是求职系统需求，本次范围外。
5. 不做演示视频。

|---|---|---|

| F-002 | 量化仪表盘：实测数字可视化（规模/测试/工程治理），每个数字带来源标注 | P0 |
| F-003 | 技术架构图：前端（Vue3.5+TS6+Pinia4+Tailwind4）/ 3D（TresJS+Three）/ 数据（Dexie 离线优先）/ 后端（FastAPI→Spring Boot 重写中）/ 部署（docker-compose + nginx + GitHub Pages）分层 | P0 |
| F-004 | STAR 项目讲述：情境-任务-行动-结果四段式，附「能扛追问」的问题预案；口径=亮点讲满+状态如实 | P0 |
| F-005 | 工程治理亮点：CI 13 job、13 篇 ADR、测试体系（Vitest/E2E/pytest）、98 个技能库、78 篇 docs | P1 |
| F-006 | 目标岗 JD 对照表：**三方向为主**（Java 后端 / 软件测试 / AI 产品，来源 work/career-os 4211 条 JD 语料分析）+ **软件交付经理（云计算）附版**（公开 JD 知识）；能力项 → tea 项目证据映射 | P1 |
| F-007 | 视觉与交互：单文件、无外部依赖可离线打开、移动端可读、视觉沿用 tea 设计语言 | P0 |
| F-008 | STAR 文档版：Markdown 文件，可直接复制粘贴 | P1 |

### 验收标准（Given-When-Then）

- **F-001**：Given 面试官打开页面 / When 首屏 5 秒内读完 / Then 能复述「这是什么、给谁、解决什么」且看到完整业务闭环图。
- **F-002**：Given 页面上任一量化数字 / When 面试官追问「这个数字哪来的」 / Then 对应来源标注可回指到仓库文件/命令；无来源数字不出现。
- **F-003**：Given 面试官查看架构 / When 逐层追问技术选型理由 / Then 每层有选型依据（ADR 或 README 出处）。
- **F-004**：Given 用户按 STAR 讲述 / When 面试官追问细节 / Then 每个结论都有仓库证据支撑，不出现无法回答的虚构细节。
- **F-005**：Given 面试官查看工程治理 / When 追问质量门禁 / Then 能列出 13 个 CI job 名称与门禁含义。
- **F-006**：Given 用户拿到目标 JD / When 逐条对照 / Then 每条能力要求映射到 ≥1 个具体证据，映射不上的明确标注差距。
- **F-007**：Given 交付前 / When 打开产物验证 / Then 单文件 <2MB、断网可开、Chrome/Edge/Safari 移动端可读、无外链依赖。
- **F-008**：Given 用户求职 / When 需要项目经历 / Then 可直接复制 STAR 文档进简历/求职信。

### Spec 门禁

1. 单切片 Spec ≤100 行（方案设计阶段遵守）。
2. 本需求为 L1/L2 级（新增展示物，不改产品逻辑）：核心可验证项走 F-007 手工验证 + F-002 数字回源核对；展示物本身不引入产品单测。
3. 实现阶段代码生成后 >10 轮返工则回需求阶段重新对齐。

## 三、非功能约束

- 性能：单文件 <2MB，本地打开 <3 秒。
- 兼容：Chrome/Edge/Safari（含移动端），断网可离线查看。
- 安全：不包含任何密钥/敏感数据；无远程请求依赖（或全部自包含）。
- 数据：所有数字标注来源与采集日期（2026-10-08 实测）。

## 四、影响分析

- 影响面：纯新增——`docs/prd/REQ-job-showcase-requirements-2026-10-08.md`、`docs/plans/PLAN-job-showcase-2026-10-08.md`（阶段 2）、HTML 产物文件（建议放 `docs/portfolio/`）、STAR 文档（`docs/portfolio/`）。
- 承重墙：不触及——不改 3D 状态机、同步逻辑、AI 降级链。
- 契约变化：无——不改 api-contract、不改数据模型。
- 回滚路径：删除新增文件即可，无迁移、无部署影响。
