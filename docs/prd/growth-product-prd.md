# 成长体系（growth）产品需求文档（PRD V2 · 企业级）

> 对齐 `frontend-product-prd.md` / `m5-agent-product-prd.md` 企业级写法。设计模式**参考行业 XP/等级系统最佳实践**（Trophy/人人都是产品经理激励体系：XP 绑核心价值行为 + 渐进阈值 + 等级解锁权益 + append-only 事件账本 + 防通胀），不造轮子。
> 事实来源（只读核实）：`V1__init.sql`（users.level/xp/preferred_* 画像字段）、`tasting_records`（品鉴=核心行为）、M5 PRD（mentor 专家依赖成长数据）。日期：2026-10-07。版本：V2.0（R1/R2 迭代后定稿）。

## 1. 背景与定位

「一盏茶」的成长纵轴：品鉴/冲泡/学茶/问答等**茶修核心行为**累积经验（XP），推动**茶修等级**（称号化：初识茶→行茶→知味→入道…）与**权益解锁**。核心目标：给用户"我在变强"的明确路径（XP 系统心理学：里程碑 + 进展可见），并让 **mentor 专家**（M5-S2）基于等级/画像做复盘。

当前状态：users 表 level/xp 字段已建（默认 1/0）；品鉴闭环已通；**XP 规则/等级公式/权益/事件账本未定**——本 PRD 补齐。

## 2. 用户角色与核心场景

| 角色 | 诉求 | 对应场景 |
|---|---|---|
| 茶小白 | 快速正反馈 | 完成首次品鉴 → 立即升级（新手期升级快） |
| 茶爱好者 | 有目标持续投入 | 攒 XP 解锁 AI 专家深度权限/称号 |
| 老茶客 | 成就外化 | 高等级称号展示（品鉴卡/分享页） |
| mentor（AI） | 数据支撑复盘 | 读等级/画像/品鉴记录 → 阶段总结（M5 联动） |

核心场景：
1. **行为即 XP**：完成冲泡/品鉴/茶知识问答 → 自动得 XP（奖励核心价值行为，非登录——行业准则）
2. **升级里程碑**：等级渐进阈值（早期快后期慢）→ 每级茶修称号 + 解锁权益
3. **称号外化**：品鉴卡/茶园/分享页展示等级称号（老茶客身份感）
4. **成长复盘**：mentor 专家按等级/画像/历史记录给"阶段总结 + 下阶段目标"

## 4. 功能域需求（Given-When-Then）

### F-R1 XP 规则（绑核心行为，配置化）

- Given 用户完成一次品鉴记录，Then 获得基础 XP（如 50）+ 品质加成（overall_score ≥4 加 20，配置化）。
- Given 用户完成冲泡流程，Then 获得冲泡 XP（如 10）。
- Given 用户完成茶知识问答（AI 或文化卡阅读），Then 获得学习 XP（如 15）。
- Given 用户连续 N 天有任意行为，Then 连续加成（streak 第 3/7 天翻倍，中断重置，可配置宽限）。
- Given 游客行为，Then 体验 XP 不落库（登录后从 0 开始，防刷）。
- Given XP 规则变更，Then 走配置表（DB/JSONB），灰度可回滚（不硬编码）。

### F-R2 等级公式与称号

- Given XP 累计达到阈值，Then 升级（渐进：L2=100、L3=250、L5=1000、L10=5000——行业渐进阈值模式，早期快后期慢）。
- Given 升级，Then 获得茶修称号（等级表：L1 初识茶/L5 行茶/L10 知味/L15 入道/L20 茶师…），称号展示于品鉴卡/分享页/茶园。
- Given 权益解锁（等级门槛），Then 解锁：L3 AI 专家会话、L5 茶园装饰位、L10 稀有茶器兑换、L15 自定义称号——按等级阶梯差异化（激励升高级）。

### F-R3 XP 事件账本（可审计防通胀）

- Given 任意 XP 入账，Then 落 `xp_events`（append-only：user_id/client_id/amount/source/level_after/created_at）。
- Given 重复提交/重放，Then client_id 幂等拒重（沿用 tasting_records 模式）。
- Given 审计需求，Then 事件流水可查（按用户/来源/时间），产出/消费报表可生成。

### F-R4 成长复盘（mentor 联动，S2）

- Given 用户请求复盘，Then mentor 读 level/xp/画像/品鉴历史聚合 → 输出"阶段总结 + 强项维度 + 下阶段目标"（M5 mentor 专家输入）。
- Given 数据不足（新用户），Then 通用引导（"完成首次品鉴开启成长路径"）。

### F-R5 展示与治理

- Given 等级变化，Then 前端即时可见（升级动画/称号弹卡，最小实现先文本）。
- Given 配置变更，Then 阈值/称号/权益表走 DB，不改代码（运营可调）。

## 5. 非功能需求矩阵

| 维度 | 要求 | 验收判据 |
|---|---|---|
| 一致性 | XP 事件账本 append-only；等级 = 事件聚合（不直接改列值）；幂等 | 重放不重复加 XP |
| 防通胀 | XP 产出速率建模（周产出 vs 阈值曲线平衡，超标告警） | 产出报表可用 + 告警触发 |
| 性能 | 等级计算 O(1)（阈值查表/二分）；品鉴落库时同步记账 | 品鉴接口延迟增幅 < 50ms |
| 可维护 | XP 规则/阈值/称号/权益全配置化（非硬编码） | 改一个 XP 值不动代码 |
| 安全 | XP/等级接口鉴权；游客不落库；防刷（行为频率限制） | 未登录不可改等级 |
| 可扩展 | 新行为源 = 新增触发配置；新权益 = 池中注册 | 30 分钟内加一种 XP 来源 |

## 6. 架构决策（ADR 候选）

| 决策 | 结论 | 理由 |
|---|---|---|
| R1 事件账本 | `xp_events` append-only + 等级聚合视图 | 行业标准（XP 事件账本），与茶园能量账本同模式，可审计防通胀 |
| R2 配置化 | 阈值/称号/权益存 DB，不硬编码 | 运营可调 + 灰度回滚 |
| R3 幂等 | user_id+client_id | 离线重放防重（沿用） |
| R4 联动 | mentor 读聚合（等级/画像/记录），S2 接线 | M5 主线复用 |

## 7. 数据模型（新表 DDL 草案，Flyway 实施时版本号顺延）

```sql
-- xp_events（XP 事件账本，append-only；与 garden_energy_events 同构）
CREATE TABLE xp_events (
    id          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id     INTEGER NOT NULL,
    client_id   VARCHAR(64) NOT NULL,
    amount      INTEGER NOT NULL,
    source      VARCHAR(30) NOT NULL,      -- tasting/brew/learn/streak
    level_after INTEGER,
    created_at  TIMESTAMP NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_xp_events_user_client ON xp_events (user_id, client_id);
-- users.level/xp 列已存在（V1）：作为聚合缓存（事件账本为准，可重建）
-- 等级阈值表 level_tiers（V4）：
--   level/name(称号)/xp_required/benefit(权益 JSONB)/sort 排序
```

- 幂等键沿用；等级 = 账本聚合（users.level 缓存可回放重建）。
