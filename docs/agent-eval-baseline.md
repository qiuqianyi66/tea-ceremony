# agent-eval-baseline — AI 协作评估基线

> 目的：为「一盏茶」的 AI 协作（本项目内所有 AI 编码助手 + 后续 agent 开发）建立可度量、可沉淀的评估基线。不是一次性打分，是持续收敛机制：每次评估的证据写回 AGENTS.md §13，规则只留救过命的。
> 来源：2026-10-06 融入 ASD-STE100 写作规范 + 大模型评估工具思路（通用能力 ↔ 专项领域两层，参考 GLUE/SuperGLUE 与 MMLU/GPQA/C-Eval 的分层思想）。状态：基线 v1，后期随 agent 开发扩展。

## 2. 评估流程（抽样会话评分）

提示词做法（"随机抽样过去一周会话 → 分析 → 沉淀"）落地为本项目流程（技能：`.harness/skills/main-dev/agent-eval`，配套脚本 `scripts/agent-eval.cjs`）：

1. **自动检查**：`node scripts/agent-eval.cjs {切片名}`——T1（三件套/review 结论行/commit 规范）、T2（summary 中 /api/ 路径已登记契约）、T4（迁移成对/零迁移声明）
2. **抽样**：每个切片/批完成时，抽 3-5 条真实会话（含用户纠正过的轮次——纠正点是最高价值样本）
2. **打分**：按 §1 维度 0/1/2 评分；任何 0 分必填证据（该轮实际说了什么）
3. **归因**：0 分是行为问题（AI 犯错）还是规则缺失（AGENTS.md 没覆盖）？
   - 行为问题 → AGENTS.md §13 加一行（AI 每次犯错加一行）
   - 规则缺失 → 补规则；连续两次同类 0 分 → 升级为硬规则（§0 或红线）
4. **收敛**：同一规则连续 3 个切片无违规 → 标记"已验证"，可考虑压缩进基线，不重复记录

## 4. 确定性七维评测（2026-10-07 新增，参照阿里 harness eval）

> 把"流程"当被测对象：`node scripts/eval-harness.cjs <切片名> [--verify]`。100% 确定性逻辑、零 LLM、3 次跑分一致；**失败必须响亮，不静默兜底**——给不了证据的维度记 0 分，不凭自报。
> 借鉴：阿里 harness eval（流程完整性/产物质量/代码正确性/效率/安全合规/迭代能力/接口验收 + honesty gap），来源 `docs/research-harness-alibaba-2026-10.md`。

| 维度 | 权重 | 一盏茶检查方式 |
|---|---|---|
| 流程完整性 | 22% | 三件套/测试产物文件存在性（文件系统不说谎）+ L3 ADR 痕迹 |
| 产物质量 | 15% | summary 结构（范围/GWT/影响）+ 反注水（>200 字且含代码块或表格） |
| 代码正确性 | 22% | **--verify 真跑 type-check / mvn compile**；不传则 0 分（拒凭自报） |
| 效率 | 10% | 切片 commit ≤8 且文档条目 ≤40 |
| 安全合规 | 8% | diff 扫描密钥/禁目录（node_modules/dist/.venv 等）/.env 提交 |
| 迭代能力 | 5% | review 结论行 🔴🟡 清零 |
| 接口验收 | 18% | summary 中 /api/ 路径均已登记 api-contract + 测试目录存在 |

- 用法：`node scripts/eval-harness.cjs m5-s2 --verify`（前端/后端自动判定）；输出 console 评分表 + `docs/agent-eval/<切片>-eval.md` 报告；总分 <60 退出码 1（门禁级）。
- 关系：与 §1 的 G/T 人评维度互补——七维是机器确定性检查（每次切片必跑），G/T 是抽样人评（证据链沉淀 §13）。

## 5. 后期扩展（agent 开发评估）

用户已拍板"一定要有评估、为后期打基础"。规划（**未立项，仅基座**）：

- **agent 行为评估**：上述 G/T 维度直接适用于 agent 任务（评审、迁移、切片），评分表 + 证据链复用
- **LLM 输出评估**：若后续 agent 调用 LLM（如 AI 切片后 teaAI LLM 输出），接入大模型评估工具思路——通用（Hugging Face Transformers/GLUE 类指标）+ 专项（茶文化领域 C-Eval 类基准，用 `tea-tasting` 基准表做领域校验）
- **评估产物**：`docs/agent-eval/` 目录落评分表，每批一份（对应 changes/ 三件套节奏）
