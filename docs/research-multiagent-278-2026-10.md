# 多智能体架构深度解析（278）精读与一盏茶 M5 对照（2026-10-07）

> 来源：语雀知识库「图灵AI大模型面试核心点(2026版)」→ 278.多智能体架构深度解析.pdf（NotebookLM 生成的 High-Availability AI Blueprint，16 页，14.5MB）。本文 = 全文精读 + 一盏茶 M5 对照 + 可借鉴清单。

## 1. 为什么需要多智能体（原文论证）

- 单体局限：幻觉与逻辑冲突。案例：竞品分析"左右互搏"——前文说 A 公司份额第一，后文说 B 公司领先。
- 根因：**架构问题，不是模型能力**。单打独斗无法自我校验与分工。
- 解法：AI 自己组队、分工、互相挑错 = Multi-Agent Architecture。

## 2. 铁三角（核心角色）

| 角色 | 隐喻 | 职责 | 关键机制 |
|---|---|---|---|
| 指挥官 Commander | 大脑/项目经理 | Think, Plan, Coordinate | **run_subagent 权限**（"招人"，主动创建子智能体）；拆解模糊需求（先拆步骤不直接查找）；用推理强模型 |
| 过滤器 Filter | 信息筛子/一线员工 | 并行处理多源（CRM/网页/研报），滤噪出 Insight | 多源并行 + 噪音过滤 |
| 审计员 Auditor | 质检员 | 质量把控 | 铁律：**绝不修改原文，只加引用标记**；显性信任：不替用户判断真假，展示来源让用户决定 |

## 3. 系统流程五阶段（任务全生命周期）

```
1.需求发起 → 2.深度规划 → 3.分发执行 → 4.汇总出稿 → 5.审计交付
   ↑________________________回退循环________________________↓
```
- 阶段1&2：模糊需求 → 指挥官拆解为战略规划（确认意图→步骤化）
- 阶段3&4：并行执行（工人A/B/C 查算法/硬件/市场）→ 指挥官拼图成因果链
- 阶段5：审计员逐句扫描生成内容找证据来源；**找不到原文 → 立刻标记风险**；交付"带证据链的报告"（金融合规/投资分析场景）

## 4. 核心能力：动态派生（硬编码 → 弹性架构）

- 硬编码缺点：预设固定数量智能体 → 资源浪费或能力瓶颈、僵化。
- 弹性架构："撒豆成兵"——按任务复杂度实时决定雇 1 个还是 50 个专家（查价格派 1 人，写白皮书生成 50 个垂类专家）。
- 实现路径四步：规划维度(Offset) → 定义人设(Definition) → 函数调用(run_subagent) → 瞬间实例化(System Instantiation，动态注入 Prompt 激活专家)。

## 5. 工程难点两个

| 难点 | 问题 | 解法 |
|---|---|---|
| 长任务"忘本" | 处理长上下文时指挥官跑偏（医疗→芯片） | **记忆模块**：Think→Plan→**Save Plan**（把计划"钉在墙上"），随时调出锚定方向 |
| 信息噪音与矛盾 | 机械执行无法判断质量 | **交错式思考**：Search→Think→Research 闭环（获取→评估发现矛盾→重新验证搜索），从机械执行升级为有判断力的验证 |

## 6. 范式转移：传统 RAG vs 多智能体

| | 传统 RAG | 多智能体 |
|---|---|---|
| 角色 | 图书管理员 | 资深研究员 |
| 行为 | 关键词匹配、机械搬运 | 主动研究，**生成与验证解耦** |
| 缺点/优点 | 无法判断冲突、缺乏深度、不知道该信谁 | 先验证再思考、先收集证据再下结论、输出有推理链条的研究成果 |

## 8. 建议优先项（对 M5 后续迭代）

1. **P0 审计员强化**：LibrarianAgent 输出增加"风险标记"——无来源的论断标"⚠ 无来源"，逐句对证据（表已就绪，纯逻辑改动）。
2. **P1 记忆落地**：用 ai_chat_sessions/ai_messages 实现"Save Plan"式会话锚定（多轮不跑偏）。
3. **P1 规划能力**：Orchestrator 对深度请求（mentor 复盘）加"意图确认→步骤规划"节点。
4. **P2 动态派生**：远期按问题复杂度派生专家数（当前 5 专家固定够用）。
5. **原则吸收**：生成与验证解耦（writer/auditor 分离）；显性信任（来源让用户判断）——M5 设计已含，后续坚持。
