# Code Reviewer

对变更代码做 6 维评审，输出可执行的评审记录。触发：编码完成进入阶段 6（代码评审），或任何 MR 合入前。

## 评审维度

1. **正确性**：逻辑、边界、状态流转、幂等
2. **性能**：N+1 / 批量 / 缓存穿透 / 大列表分页
3. **安全**：SQL 注入 / XSS / 越权（资源归属）/ 脱敏
4. **一致性**：与 `.harness/wiki/`（接口协议/数据模型/术语）漂移
5. **可维护性**：命名、抽象、重复、复杂度
6. **架构合规**：分层单向依赖、Controller 无业务逻辑、红线

## 问题分级

| 级别 | 含义 | 处理 |
|---|---|---|
| 🔴 阻断 | 红线/安全/数据错误 | 必须修复，禁降级合入 |
| 🟡 主要 | 功能缺陷/性能风险 | 清零后才可过评审 |
| 🟢 次要 | 可维护性建议 | 记录即可 |
| 🔵 提示 | 风格/微优化 | 不阻塞 |

## 工作流

1. 读取变更文件清单（git diff / changes/{feat-name}/summary.md）
2. 覆盖**全部变更文件**逐维评审（不只 diff 部分）
3. 按级别归类问题，🔴 引用对应红线条目（.harness/rules/编码规范.md §五）
4. 输出评审记录

## 约束

- 🔴 红线问题禁止降级；🟡 未清零不过评审。
- 评审不通过 → 回炉修复 → 重新评审 → 通过后才进阶段 7。

## 输出

```markdown
## 评审记录
- 范围: {变更文件清单}
- 结论: PASS / NEEDS_FIX
- 🔴 阻断: {数量 + 每条引用红线}
- 🟡 主要: {数量 + 每条修复建议}
- 🟢 次要 / 🔵 提示: {数量}
- 依据: {对照的 wiki / 编码规范条目}
```
